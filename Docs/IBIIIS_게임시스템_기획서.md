# IBIIIS 게임 시스템 기획서

작성일: 2026-10-01 · 갱신일: 2026-10-03 · 버전: 0.4 · 상태: 작성 중

사용자가 제공하는 정보를 누적하는 기획서다. 이후 대화에서 수정한 규칙을 기존 PDF와 HTML보다 우선한다. 확정은 현재 대화에서 정한 내용이며, 최종 출시 사양을 의미하지 않는다.

## 1. 게임 개요 — PDF 기반 초안

| 항목 | 내용 |
|---|---|
| 타이틀 | (제발!) 제 말을 끝까지 들 |
| 플랫폼 | Steam(PC) |
| 장르 | 액션, 어드벤처, 퍼즐 |
| 그래픽 | 2.5D 쿼터뷰. 3D 맵 위에 플레이어·적·소품 등 맵을 제외한 오브젝트를 2D 스프라이트로 배치 |
| 핵심 콘셉트 | 싸움을 무서워하는 주인공이 이벤트 보상 망토를 얻기 위해 던전을 돌파한다. |
| 전투 목표 | 직접 공격하지 않고 회피와 유도를 통해 적들이 서로 공격하여 자멸하게 한다. |
| 이야기 분위기 | 소심한 주인공의 말과 행동에서 발생하는 오해를 활용한 유머 중심 전개 |
| 진행 구조 | 세계관 소개 → 스토리와 전투 반복 → 최종 전투 → 엔딩 |
| 목표 동선 | 중간 던전 클리어 → 입장권 획득 → 이벤트 보스전 → 망토 획득 |

그래픽 구성은 돈스타브와 컬트 오브 더 램처럼 입체적인 맵에 평면 스프라이트 오브젝트를 배치하는 방식을 참고한다. 그림체, 픽셀 아트 여부, 카메라 각도와 상세 에셋 규격은 아직 정하지 않았다. 제작 규격은 [에셋 제작 가이드](IBIIIS_에셋_제작_가이드.md)에 기록한다.

## 2. 전투 공간과 시간 — 확정

2026-10-02 프로토타입 카메라 변경: 사용자 요청으로 Perspective 투영과 정면 방향을 적용했다. 기존 대각선 좌우 회전을 제거했으며, 구체적인 설정과 편집 위치는 [개발 및 사용 가이드](IBIIIS_개발_및_사용_가이드.md)의 공용 카메라 설정을 따른다. 기존 쿼터뷰 참고와 별개로 현재 프로토타입은 이 변경을 우선한다.

- 맵은 격자로 구성된다.
- 턴 시스템을 제거한다. 플레이어가 이동하는 동안 게임 시간이 실시간으로 흐르고 도착하면 정지한다.
- 입력 대기 중에는 게임 시간이 흐르지 않는다. 이동 불가 입력도 시간을 진행시키지 않는다.
- 기본 이동 시간은 GlobalPlayerSettings에서 설정한다. 이동 중 추가 입력은 무시한다. 회피기(대시·구르기)의 시간 규칙은 아직 미정이다.
- 플레이어는 적의 공격을 피하면서 적들이 서로 공격하도록 유도한다.
- 적의 시간 기반 행동 주기와 충돌·피해 처리 순서는 미정이다.

## 3. 플레이어 행동

| 행동 | 조작 | 방향 | 이동 거리 | 쿨타임 | 행동 시간 |
|---|---|---|---|---|---|
| 기본 이동 | WASD | 상하좌우 | 1칸 | 이동 중 추가 입력 무시 | 공용 설정의 이동 시간 |
| 대시 | 미정 | 미정 | 한 번에 2칸 | 있음, 수치·감소 기준 미정 | 미정 |
| 구르기 | 미정 | 대각선 | 1칸 | 있음, 수치·감소 기준 미정 | 미정 |

추가 결정 사항: 방향 지정 방식, 회피기 무적 여부, 중간 칸의 충돌·피해 판정, 벽·적 통과 여부, 쿨타임 적용 및 갱신 시점.

## 4. 적 행동 규칙

### 4.1 확정된 구조

- 각 적은 고유한 행동 패턴을 가진다. 기존 턴 카운터 계획은 폐기하며 시간 기반 실행 구조는 후속 설계한다.
- 각 적은 플레이어 인식범위를 가진다. 적별 범위는 데이터테이블에서 관리한다.
- 행동 주기에 따라 이동하거나 공격한다.
- 적별 주기의 단위·수치는 아직 정하지 않았다.
- 적의 종류, 체력, 구체적인 패턴 및 수치는 아직 정하지 않았다.

### 4.2 미정인 공통 규칙

- 첫 행동까지의 대기 시간과 타이머 초기화·갱신 시점
- 여러 적이 동시에 행동할 때의 처리 순서 및 동시 판정 여부
- 이동과 공격의 분리·결합 여부, 패턴 전환 및 반복 방식
- 타깃 선정, 방향 고정 및 공격 예고 방식
- 플레이어 인식범위의 형태·크기·거리 계산 방식, 장애물에 의한 시야 차단 여부
- 인식 판정 시점, 인식 전·후 행동 및 범위 이탈 시 인식 유지 여부
- 적끼리의 공격·충돌 피해, 장애물 및 점유 칸 처리
- 플레이어 체력, 피격·사망 규칙과 전투 승리·실패 조건

## 5. 적 데이터테이블 구조 — 작성용 뼈대

연결 파일: [IBIIIS_적_데이터테이블.xlsx](IBIIIS_적_데이터테이블.xlsx)

아래 열은 이전 턴 기반 초안이다. 행동 주기(턴)는 현재 시간 기반 규칙에 맞춰 후속 개정이 필요하며 이번에는 엑셀을 변경하지 않았다. 특정 적이나 전투 규칙을 확정하지 않는다. 현재는 실제 적·패턴 레코드가 없으며, 빈 입력 행만 제공한다.

| 시트 | 한 행의 의미 | 주요 항목 |
|---|---|---|
| 적 기본정보 | 적 종류 하나 | 적 ID, 이름, 체력, 행동 주기(턴), 패턴 ID, 기획 상태, 비고, 플레이어 인식범위 |
| 행동 패턴 | 패턴 하나 | 패턴 ID, 이름, 행동 순서, 이동 규칙, 공격 규칙, 타깃·예고 규칙, 기획 상태, 비고 |

### 작성 원칙

1. 적 ID와 패턴 ID는 각각 중복되지 않는 식별자로 관리한다.
2. 적 기본정보의 패턴 ID는 행동 패턴 시트의 패턴 ID를 참조한다. 초기에는 기본 패턴 ID 하나를 기록하고, 복수 패턴 구조가 필요해지면 확장한다.
3. 체력과 주기는 숫자로 입력한다. 미정은 빈칸으로 두며 0으로 대체하지 않는다.
4. 행동 순서와 이동·공격 규칙은 우선 기획 문장으로 기록한다. 구현 방식이 정해지면 필요한 값을 개별 열로 분리한다.
5. 수치와 설정은 데이터에서 관리하고, 시간 진행·이동 검사·공격 및 피해 판정은 코드에서 구현하는 방향으로 작업한다.
6. 이 파일은 기획용 데이터테이블이다. 게임이 바로 읽는 런타임 데이터 형식이나 자동 연동은 아직 구현하지 않았다.
7. 후속 정보가 들어오면 공통 규칙은 이 기획서에, 적별 설정과 패턴은 엑셀에 반영한다.
8. 플레이어 인식범위는 형태와 크기가 결정되기 전까지 기획 문장으로 기록한다. 단위와 판정 방식이 정해지면 필요한 열을 분리한다. 인식범위를 공격범위와 동일한 것으로 간주하지 않는다.

## 6. 프로토타입 참고 범위

HTML은 격자 이동과 적별 행동 주기를 확인하기 위한 참고 자료다. 현재는 플레이어 이동 중에만 게임 시간이 흐르는 구조를 적용한다. HTML의 체스형 적, 점프, 체력 수치, 생성 주기, 무적 시간 등은 확정 기획으로 가져오지 않는다. 현재 회피기는 대시와 구르기다.

### 기본 맵·이동 프로토타입 — 임시 규칙

2026-10-02 사용자의 구현 요청에 따라 별도 맵 편집 창과 기본 이동을 추가했다. 아래 값은 테스트용 기본값이며 위의 미정 전투 규칙을 최종 확정하지 않는다.

- 평면 격자에서 기본 이동만 구현한다. 빈 칸·이동 불가 타일·맵 경계로 이동할 수 없다.
- 한 칸 이동 시간의 임시 기본값은 0.25초이며 GlobalPlayerSettings에서 변경한다. 이동 시작 시 시간을 고정하고 도착 시 논리 좌표를 확정한다.
- 한 번의 WASD 누름에 한 칸을 보간 이동한다. 대기 중에는 시간 정지, 이동 중에만 시간 진행. 전용 걷기 애니메이션 클립은 아직 연결하지 않았다.
- 시작 위치는 맵마다 하나이며 이동 가능한 칸에 지정한다. 맵 저장 원본과 실행 위치·이동 상태을 분리한다.
- 플레이 검증은 사용자 확인 대기다. 사용 절차와 개발 검증은 [개발 및 사용 가이드](IBIIIS_개발_및_사용_가이드.md)를 따른다.
