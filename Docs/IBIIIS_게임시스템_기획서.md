# IBIIIS 게임 시스템 기획서

작성일: 2026-10-01 · 갱신일: 2026-10-07 · 버전: 0.6 · 상태: 작성 중

사용자가 제공하는 정보를 누적하는 기획서다. 이후 대화에서 수정한 규칙을 기존 PDF와 HTML보다 우선한다. 확정은 현재 대화에서 정한 내용이며, 최종 출시 사양을 의미하지 않는다. 현재 프로토타입에 채택한 전투 규칙의 세부 판정·조작·사용 절차는 [전투 및 적 배치 가이드](IBIIIS_전투_및_적배치_가이드.md)가 담당한다.

## 1. 게임 개요 — PDF 기반 초안

| 항목 | 내용 |
|---|---|
| 타이틀 | (제발!) 제 말을 끝까지 들 |
| 플랫폼 | Steam(PC) |
| 장르 | 액션, 어드벤처, 퍼즐 |
| 그래픽 | 2.5D 쿼터뷰. 3D 맵 위에 플레이어·적·소품 등 맵을 제외한 오브젝트를 2D 스프라이트로 배치 |
| 핵심 콘셉트 | 싸움을 무서워하는 주인공이 이벤트 보상 망토를 얻기 위해 던전을 돌파한다. |
| 전투 목표 | 직접 공격하지 않고 회피와 유도를 통해 적들이 서로 공격하여 자멸하게 한다. |
| 이야기 분위기 | 소심한 주인공의 말과 행동에서 발생하는 오해를 활용한 유머 중심 전개 |
| 진행 구조 | 세계관 소개 → 스토리와 전투 반복 → 최종 전투 → 엔딩 |
| 목표 동선 | 중간 던전 클리어 → 입장권 획득 → 이벤트 보스전 → 망토 획득 |

그래픽 구성은 돈스타브와 컬트 오브 더 램처럼 입체적인 맵에 평면 스프라이트 오브젝트를 배치하는 방식을 참고한다. 그림체, 픽셀 아트 여부와 상세 에셋 규격은 아직 정하지 않았다. 제작 규격은 [에셋 제작 가이드](IBIIIS_에셋_제작_가이드.md)에 기록한다.

현재 프로토타입 카메라는 사용자 요청(2026-10-02)에 따라 Perspective 투영과 정면 방향(좌우 회전 없음)을 쓴다. 최종 카메라 각도는 미정이며, 설정과 편집 위치는 [개발 및 사용 가이드](IBIIIS_개발_및_사용_가이드.md)의 공용 카메라 설정을 따른다.

## 2. 전투 공간과 시간

확정:

- 맵은 격자로 구성된다.
- 턴 시스템을 쓰지 않는다. 플레이어가 행동하는 동안 게임 시간이 실시간으로 흐르고, 행동이 끝나면 정지한다.
- 입력 대기 중에는 게임 시간이 흐르지 않는다. 이동 불가 입력도 시간을 진행시키지 않는다. 행동 중 추가 입력은 무시한다.
- 플레이어는 적의 공격을 피하면서 적들이 서로 공격하도록 유도한다.

프로토타입 채택 규칙(사용자 확인, 2026-10-05~06):

- 플레이어 행동 한 번에 플레이어와 적이 동시에 움직이기 시작한다. 양쪽 행동이 모두 끝난 뒤 공격·피격을 판정하고 다시 입력을 기다린다.
- 기본 이동 시간과 적 한 칸 이동 시간은 GlobalPlayerSettings에서 설정하는 임시 연출 값이며 판정 결과를 바꾸지 않는다.
- 맵은 사용자가 11×11부터 제작한다.

## 3. 플레이어 행동

| 행동 | 기본 조작 | 방향 | 이동 거리 | 제한 | 행동 시간 |
|---|---|---|---|---|---|
| 기본 이동 | WASD/방향키 | 상하좌우 | 1칸 | 없음 | 공용 설정의 이동 시간 |
| 대기 | Space | — | 0칸 | 없음 | 이동 시간과 같음 |
| 대시 | Shift+방향 | 상하좌우 | 직선 2칸 | 회피기 제한 공유 | 이동 시간의 2배 |
| 구르기 | Q/E/Z/C | 대각선 | 1칸 | 회피기 제한 공유 | 이동 시간과 같음 |

- 프로토타입 채택 규칙: 대시·구르기를 쓰면 다음 한 번의 일반 이동 또는 대기 동안 회피기를 쓸 수 없다. 무적은 없다. 대시는 중간 칸의 적·빈칸을 통과하지 못한다. 키 배치는 Input Actions 에셋에서 바꿀 수 있다.
- 미정: 회피기 쿨타임의 최종 수치와 표시 방식, 구르기의 장애물 대각선 통과 제한.

## 4. 적 행동 규칙

### 4.1 확정된 구조

- 각 적은 고유한 행동 패턴을 가진다. 기존 턴 카운터 계획은 폐기했다.
- 각 적은 플레이어 인식범위를 가진다. 인식범위를 공격범위와 같은 것으로 보지 않는다.
- 행동 패턴에 따라 이동하거나 공격한다.

### 4.2 프로토타입 채택 규칙

세부 판정과 적 3종(Enemy001~003)의 설정은 [전투 및 적 배치 가이드](IBIIIS_전투_및_적배치_가이드.md)를 따른다.

- 적은 플레이어 행동 한 번마다 자신의 행동 목록(조준·전진·회전)을 순서대로 수행한다. 모든 적이 동시에 행동한다.
- 인식·조준은 플레이어의 행동 시작 직전 위치만 쓴다. 적은 플레이어가 이번 행동에서 어디로 갈지 모른다.
- 인식·공격 범위는 적별로 진행 방향 기준 칸 목록으로 정한다.
- 적끼리는 같은 칸에 도착할 때만 함께 죽는다(공격 범위로는 죽지 않음).
- 살아남은 적의 공격 범위나 이동 경로에 플레이어가 있으면 패배, 배치한 적이 전멸하면 승리한다.

### 4.3 미정인 공통 규칙

- 적 체력과 플레이어 체력(현재 프로토타입은 한 번 맞으면 패배)
- 패턴 전환 방식과 `Turn` 행동을 쓰는 패턴
- 공격 예고 방식과 전투 UI
- 장애물에 의한 시야 차단 여부와 내부 장애물 처리
- 적별 패턴과 수치의 최종 확정

## 5. 적 데이터테이블 구조 — 작성용 뼈대

연결 파일: [IBIIIS_적_데이터테이블.xlsx](IBIIIS_적_데이터테이블.xlsx)

아래 열은 이전 턴 기반 초안이며, 행동 주기(턴) 열은 현재 규칙에 맞춰 개정이 필요하다. 현재 엑셀에는 실제 적·패턴 레코드가 없고 빈 입력 행만 있다. 게임의 실행 기준은 적 프리팹이다([데이터 관리 문서](IBIIIS_데이터_관리_문서.md)).

| 시트 | 한 행의 의미 | 주요 항목 |
|---|---|---|
| 적 기본정보 | 적 종류 하나 | 적 ID, 이름, 체력, 행동 주기(턴), 패턴 ID, 기획 상태, 비고, 플레이어 인식범위 |
| 행동 패턴 | 패턴 하나 | 패턴 ID, 이름, 행동 순서, 이동 규칙, 공격 규칙, 타깃·예고 규칙, 기획 상태, 비고 |

### 작성 원칙

1. 적 ID와 패턴 ID는 각각 중복되지 않는 식별자로 관리한다.
2. 적 기본정보의 패턴 ID는 행동 패턴 시트의 패턴 ID를 참조한다. 초기에는 기본 패턴 ID 하나를 기록하고, 복수 패턴 구조가 필요해지면 확장한다.
3. 체력과 주기는 숫자로 입력한다. 미정은 빈칸으로 두며 0으로 대체하지 않는다.
4. 행동 순서와 이동·공격 규칙은 우선 기획 문장으로 기록한다. 구현 방식이 정해지면 필요한 값을 개별 열로 분리한다.
5. 수치와 설정은 데이터에서 관리하고, 시간 진행·이동 검사·공격 및 피해 판정은 코드에서 구현한다.
6. 이 파일은 기획용 데이터테이블이다. 게임이 바로 읽는 런타임 형식이나 자동 연동은 없다.
7. 후속 정보가 들어오면 공통 규칙은 이 기획서에, 적별 설정과 패턴은 엑셀에 반영한다.
8. 플레이어 인식범위는 형태와 크기가 결정되기 전까지 기획 문장으로 기록한다. 인식범위를 공격범위와 동일한 것으로 간주하지 않는다.

## 6. 참고 자료의 적용 범위

- 사용자가 제공한 전투 자료(Word·HTML·Excel)의 판정을 기준으로 삼았다. 자료끼리 다른 부분의 채택 결과는 전투 및 적 배치 가이드에 있다.
- HTML의 체스형 적, 점프, 체력 수치, 생성 주기, 무적 시간 등은 확정 기획으로 가져오지 않는다. 현재 회피기는 대시와 구르기다.
- 제공 자료의 배치별 전수 탐색 결과(8행동 이전 사망 금지, 30행동 이내 전멸, 8~12분 플레이 시간 등)는 현재 규칙에서 재검증하지 않았으며 확정 목표로 보지 않는다.

## 7. 미니맵과 스테이지 진행 — 시험 중

사용자 결정(2026-10-07)에 따라 `feature/overworld-minimap` 브랜치에서 시험한다. 사용 절차는 [개발 및 사용 가이드](IBIIIS_개발_및_사용_가이드.md)의 미니맵 항목에 있다.

프로토타입 채택 규칙:

- 전투 스테이지 사이를 오가는 미니맵(Overworld)을 둔다. 플레이어를 따라가는 원경 카메라로 본다.
- 플레이어는 WASD로 자유 이동한다(격자 없음, 대각선 포함). 위만 누르면 뒷모습, 아래만 누르면 앞모습, 대각선을 포함해 좌우가 섞이면 옆모습을 보인다.
- 상호작용 키는 F다(전투의 E 구르기와 겹치지 않게).
- NPC에게 말을 걸면 머리 위 말풍선에 대사 몇 줄을 차례로 보여 준다. 대화창은 아직 만들지 않는다.
- 스테이지 입구에서 F를 누르면 전투에 들어간다. 승리하면 클리어를 기록하고 클리어 팝업을 띄우며, 확인하면 미니맵으로 돌아온다. 패배해도 팝업 확인 후 미니맵으로 돌아온다.
- 클리어 기록은 저장되어 다음 실행에도 남는다.
- 미니맵은 전투의 입력 대기 중 시간 정지와 분리되어 일반 시간으로 움직인다.

미정:

- 승리 후 미니맵으로 돌아오기 전의 스토리 대화창 연출(추후 검토)
- 정식 대화창, 선택지·분기
- 스테이지 해금 조건과 순서, 클리어 후 재도전 보상
- 전투 도중 미니맵으로 나가는 방법
- 미니맵의 맵 구성, 저장 슬롯

- 사용자 대화(2026-10-07): 미니맵 자유 이동·방향 표시·F 상호작용·말풍선·승패 후 복귀·클리어 저장·카메라 추적
