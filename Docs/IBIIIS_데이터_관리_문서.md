# IBIIIS 데이터 관리 문서

작성일: 2026-10-01 · 버전: 0.1 · 상태: 준비용 초안

## 용도

어떤 파일에서 값을 수정하고, 그 값이 게임에 어떻게 반영되는지 기록한다. 기획 데이터와 실제 실행 데이터의 차이, ID 참조, 가져오기 범위를 명확히 관리하기 위한 문서다.

## 현재 문서 관리 기준

- 앞으로 이 프로젝트에서 관리할 기획서와 데이터테이블은 같은 `Docs/` 폴더의 파일이다.
- 프로젝트 외부의 기존 `rpdl/outputs` 파일은 보관본으로 남겨두었다. 두 위치는 자동 동기화되지 않는다.
- 외부 파일의 변경을 다시 가져와야 할 때는 차이를 확인하고 필요한 내용만 반영한다. 프로젝트 사본을 무조건 덮어쓰지 않는다.
- [게임 시스템 기획서](IBIIIS_게임시스템_기획서.md)는 공통 규칙을 관리한다.
- [적 데이터테이블](IBIIIS_적_데이터테이블.xlsx)은 적별 설정과 패턴을 관리하는 기획용 파일이다. 현재 실제 적·패턴 레코드는 없다.
- 적 데이터의 런타임 형식과 엑셀 자동 연동은 미구현이다. 맵·타일은 아래 Unity 에셋을 실행 데이터 기준으로 사용한다.
- 엑셀을 저장하는 것만으로 게임에 자동 반영된다고 간주하지 않는다.

## 항목별 관리 위치

| 항목 | 현재 기획 기준 | 실제 실행 기준·반영 방법 |
|---|---|---|
| 공통 시간·이동·전투 규칙 | 게임 시스템 기획서 | 구현 시 기록 |
| 적 ID·이름·체력·행동 주기·인식범위 | 엑셀의 적 기본정보 시트 | 구현 시 기록 |
| 패턴 ID·행동 순서·이동·공격·타깃 규칙 | 엑셀의 행동 패턴 시트 | 구현 시 기록 |
| 이미지·애니메이션·효과음 참조 | 엑셀의 현재 열 구조에 없음 | Unity 연결 위치를 구현 후 기록 |
| 현재 체력·위치·카운터 | 개체별 실행 상태 | 초기화·저장 방식 구현 시 기록 |

미구현 항목은 실행 데이터 구현 시 실제 편집 위치와 반영 방식을 확정한다. 수동 반영 기간에는 기획 변경과 게임 반영 여부를 구분해 기록한다.

## 맵 실행 데이터 — 2026-10-03 갱신

맵 에디터의 `새 맵`은 GridMap 에셋과 이를 참조하는 씬을 같은 이름으로 함께 생성한다. 이후 타일·시작 위치 수정의 관리 기준은 GridMap 에셋이며 씬에 배치를 복제하지 않는다. 기존 파일이 있으면 번호를 붙이고, 씬 생성 실패 시 새 쌍만 정리한다. 생성 직후 빈 맵은 편집 가능한 상태일 뿐 플레이 준비 완료가 아니다.

- `GridMap` ScriptableObject: 가로·세로, 칸별 이동 영역, 시작 위치, 바닥 재질, 임시 외곽 여유·이동 영역 색상. 기존 셀 ID와 팔레트는 호환용으로 보존한다. 기본 바닥은 내부 예약 ID `__ibiiis_walkable__`을 사용한다. 종류별 바닥은 TileDefinition의 안정적인 ID를 셀에 저장하고 팔레트 참조로 연결한다. 맵 편집기에서 배치를 수정한다. 예시는 `Assets/IBIIIS/Content/StarterMap.asset`이다.
- `TileDefinition` ScriptableObject (이동 바닥 종류): 숨겨진 고유 ID, 표시 이름, 편집기/대체 표시 색상, 선택 평면 재질. 이동 가능 여부·옛 프리팹 필드는 호환용으로 숨겨 보존하며 새 바닥은 항상 이동 가능하다. 옛 프리팹은 생성하지 않는다. 예시는 같은 폴더의 `Floor.asset`, `Wall.asset`이다. ID는 생성 시 발급하며 표시 이름·경로가 바뀌어도 유지한다.
- 칸 데이터의 빈 ID는 빈 공간이며 이동할 수 없다. 존재하지 않는 ID·중복 ID·누락 참조·잘못된 시작 위치는 실행 전에 오류로 보고한다. 일부만 생성하는 방식으로 오류를 숨기지 않는다.
- 바닥 재질은 맵별 선택 참조다. 비어 있으면 Resources의 `IBIIIS/DefaultGround` 재질을 사용한다. 이동 영역과 환경은 자동 연동하지 않는다. 엑셀과 연결하지 않는다. 기본 에셋 생성기는 기존 에셋을 덮어쓰지 않는다.
- 저장한 맵은 테스트 씬의 `GridMapPlayer.map`에서 참조한다. 실행 시 `GridSession`이 이동 가능 정보와 시작 위치를 복사하고 현재 위치·목적지·이동 진행률을 별도로 관리한다. 실행 중 원본 수정은 다음 시작 시 반영된다.
- 실제 편집·저장·테스트 씬 생성 절차와 검증 결과는 [개발 및 사용 가이드](IBIIIS_개발_및_사용_가이드.md)에 있다.
- Scene 미리보기는 맵·타일 에셋을 읽어 임시 외형만 생성한다. 생성 오브젝트·임시 머티리얼은 저장 제외이며 런타임 세션을 생성하지 않는다. 공용 카메라 Projection·각도·화각은 `Assets/IBIIIS/Content/GlobalCameraSettings.asset`에서 관리한다. 씬의 Grid Map Player가 이를 참조하며 Auto Fit Camera를 끄면 씬 Camera의 개별 설정을 유지한다. 맵 에셋에는 카메라 설정을 저장하지 않는다.

## 현재 데이터 작성 기준

2026-10-03 시간 기반 이동으로 전환했다. 적 데이터테이블의 기존 턴 단위 주기 열은 이전 초안이며 현재 실행 시스템과 연결되지 않는다. 적 시스템 구현 시 시간 기준 규격을 별도 확정해야 한다. 이번 작업에서는 엑셀 구조를 변경하지 않았다.

맵별 환경 배치는 `GridMap.environmentPrefab`이 참조하는 프리팹에서 관리한다. Scene에는 연결된 인스턴스와 인스턴스/원본 참조를 저장한다. Scene override는 해당 씬에만 적용되고, 다른 테스트 씬으로 전파하려면 환경 프리팹에 적용해야 한다. 타일 자동 생성은 환경 인스턴스를 변경하지 않는다. 환경 교체·해제 시 미적용 변경이 있으면 편집 동기화를 보류한다. 외형의 배치·Collider는 현재 격자 이동 데이터로 가져오지 않는다. 엑셀 연동은 없다.

플레이어 실행 설정은 `Assets/IBIIIS/Content/GlobalPlayerSettings.asset`에서 관리한다. 외형 프리팹, 한 칸 이동 시간(초), 이동 가능 칸 표시 여부·색상·재질을 소유한다. 이동 시간은 각 이동 시작 시 개별 세션에 복사하며 실행 상태는 공용 설정에 기록하지 않는다. 기존 외형 참조는 유지하고 턴 비용·카운터는 제거했다. 저장된 예전 턴 필드는 더 이상 읽지 않는다. 설정 편집·검증 절차는 개발 및 사용 가이드를 따른다.

- 적 ID와 패턴 ID는 각각 중복 없는 식별자로 관리한다. 이름이 바뀌어도 같은 콘텐츠의 ID를 임의로 바꾸지 않는다.
- 적 기본정보의 패턴 ID는 행동 패턴 시트의 패턴 ID를 참조한다.
- ID 접두사·번호 규칙과 삭제된 ID의 재사용 정책은 미정이다.
- 체력과 행동 주기는 숫자로 기록한다. 미정은 빈칸으로 두고 0으로 대체하지 않는다. 정확한 허용 범위는 규칙 확정 시 정의한다.
- 이동·공격·타깃 규칙은 현재 기획 문장이다. 구조화된 실행 데이터로 자동 해석할 수 있다고 가정하지 않는다.
- 인식범위의 형태·단위·판정 방식은 미정이며 공격범위와 구분한다.
- 기획 상태의 선택값은 초안, 검토 중, 확정이다. 기획 확정은 구현 완료나 게임 반영 완료를 의미하지 않는다.

## 가져오기 도입 시 결정할 항목 — 현재 사용 불가

| 항목 | 결정·기록할 내용 |
|---|---|
| 입력 형식 | XLSX 직접 처리 또는 별도 변환 형식 |
| 필드 대응 | 시트·열과 런타임 필드의 매핑, 자료형·단위 |
| 관리 권한 | 가져오기로 덮어쓸 값과 Unity에서 보존할 값 |
| 검증 | 중복 ID, 누락 참조, 빈칸, 범위 밖 수치의 처리 |
| 반영 방식 | 변경 미리보기, 신규·수정·삭제 처리, 실행 중 반영 여부 |
| 실패 처리 | 사전 검증, 부분 반영 방지, 복구 방법 |
| 구조 변경 | 스키마 버전, 필드 변경과 기존 데이터 이전 |

외형·연출 참조는 별도 매핑을 명시적으로 설계하기 전까지 가져오기 대상으로 삼지 않는다. 실제 가져오기 도구가 구현되면 위 표를 구체화하고 사용 절차는 [개발 및 사용 가이드](IBIIIS_개발_및_사용_가이드.md)에 연결한다.
