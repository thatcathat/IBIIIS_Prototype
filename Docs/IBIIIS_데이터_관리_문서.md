# IBIIIS 데이터 관리 문서

작성일: 2026-10-01 · 갱신일: 2026-10-06 · 버전: 0.2 · 상태: 작성 중

## 용도

어떤 파일에서 값을 수정하고, 그 값이 게임에 어떻게 반영되는지 기록한다. 기획 데이터와 실제 실행 데이터의 차이, ID 참조, 가져오기 범위를 명확히 관리하기 위한 문서다.

## 현재 문서 관리 기준

- 이 프로젝트에서 관리할 기획서와 데이터테이블은 같은 `Docs/` 폴더의 파일이다.
- 프로젝트 외부의 기존 `rpdl/outputs` 파일은 보관본이다. 두 위치는 자동 동기화되지 않는다. 외부 파일의 변경을 다시 가져와야 할 때는 차이를 확인하고 필요한 내용만 반영한다. 프로젝트 사본을 무조건 덮어쓰지 않는다.
- [게임 시스템 기획서](IBIIIS_게임시스템_기획서.md)는 공통 규칙을, [전투 및 적 배치 가이드](IBIIIS_전투_및_적배치_가이드.md)는 현재 채택한 전투 규칙과 적 설정을 관리한다.
- [적 데이터테이블](IBIIIS_적_데이터테이블.xlsx)은 적별 설정과 패턴을 관리하는 기획용 파일이다. 현재 실제 적·패턴 레코드는 없고, 행동 주기(턴) 열은 이전 턴 기반 초안이다. 엑셀 자동 연동은 없으며, 엑셀을 저장하는 것만으로 게임에 반영된다고 간주하지 않는다.

## 항목별 관리 위치

| 항목 | 현재 기획 기준 | 실제 실행 기준·반영 방법 |
|---|---|---|
| 공통 시간·이동·전투 규칙 | 게임 시스템 기획서 | 코드(`Runtime/GridSession.cs`)가 판정을 구현한다. 채택 규칙은 전투 및 적 배치 가이드 |
| 적 ID·이름 | 엑셀의 적 기본정보 시트 | 적 프리팹 `EnemyDefinition`의 Enemy Id. 표시 이름 필드는 없다 |
| 적 체력·행동 주기 | 엑셀의 적 기본정보 시트 | 미구현. 현재 적은 체력이 없고, 플레이어 행동 한 번마다 행동 목록을 수행한다 |
| 적 행동 목록(조준·전진·회전 순서)·이동 칸·인식·공격 범위 | 엑셀 행동 패턴 시트(기획 문장) | **적 프리팹의 `EnemyDefinition`이 실행 기준**이다. 값을 옮길 때는 프리팹을 직접 수정한다. 기본 3종은 `Characters/Enemies/EnemyNNN/` 프리팹 |
| 패턴 ID·패턴 전환·타깃·예고 규칙 | 엑셀의 행동 패턴 시트 | 미구현. 패턴 ID 없이 적 프리팹마다 행동 목록 하나를 가진다 |
| 플레이어 외형·이동 시간·표시·입력·연출 설정 | 게임 시스템 기획서 | `Assets/IBIIIS/Settings/GlobalPlayerSettings.asset`과 연결된 설정 에셋(아래) |
| 이미지·애니메이션·효과음 참조 | 엑셀의 현재 열 구조에 없음 | 플레이어는 `PlayerVisual.prefab`의 슬롯, 적은 프리팹의 `Visual` 자식, 충돌 연출은 `CollisionFeedback.asset`. 절차는 [에셋 제작 가이드](IBIIIS_에셋_제작_가이드.md) |
| 스테이지 클리어 기록 | 게임 시스템 기획서의 미니맵 항목 | `Application.persistentDataPath/IBIIIS_progress.json`(아래 클리어 기록). 스테이지 ID는 미니맵의 `StageEntrance`에서 정한다 |
| 현재 위치·방향·생존·인식·회피기 쿨다운 | 개체별 실행 상태 | `GridSession`과 `EnemyState`에만 저장한다. 공유 설정·프리팹·맵 에셋에 기록하지 않으며 저장·불러오기 기능은 없다 |

## 맵 실행 데이터

맵 에디터의 `새 맵`은 GridMap 에셋과 이를 참조하는 씬을 같은 이름으로 함께 생성한다. 이후 타일·시작 위치·적 배치 수정의 관리 기준은 GridMap 에셋이며 씬에 배치를 복제하지 않는다. 기존 파일이 있으면 번호를 붙이고, 씬 생성 실패 시 새 쌍만 정리한다. 생성 직후 빈 맵은 편집 가능한 상태일 뿐 플레이 준비 완료가 아니다.

- `GridMap` ScriptableObject: 가로·세로, 칸별 이동 영역, 시작 위치, 적 배치(프리팹 참조·칸 좌표·방향), 배경 바닥 재질, 외곽 여유·기본 바닥 색상, 환경 프리팹. 기존 셀 ID와 팔레트는 호환용으로 보존한다. 기본 바닥은 내부 예약 ID `__ibiiis_walkable__`을 사용한다. 종류별 바닥은 TileDefinition의 안정적인 ID를 셀에 저장하고 팔레트 참조로 연결한다. 맵 편집기에서 배치를 수정한다. 예시는 `Assets/IBIIIS/Maps/StarterMap/StarterMap.asset`이다.
- `TileDefinition` ScriptableObject (이동 바닥 종류): 숨겨진 고유 ID, 표시 이름, 편집기/대체 표시 색상, 선택 평면 재질. 이동 가능 여부·옛 프리팹 필드는 호환용으로 숨겨 보존하며 새 바닥은 항상 이동 가능하다. 예시는 `Assets/IBIIIS/Tiles/Floor.asset`, `Floor2.asset`이다. 삭제된 `Wall.asset`이 StarterMap·TestMap·TestMap3 팔레트에 누락 참조로 남아 있다(맵 에디터 오류 표시, 미해결). ID는 생성 시 발급하며 표시 이름·경로가 바뀌어도 유지한다.
- 칸 데이터의 빈 ID는 빈 공간이며 이동할 수 없다. 존재하지 않는 ID·중복 ID·누락 참조·잘못된 시작 위치는 실행 전에 오류로 보고한다. 일부만 생성하는 방식으로 오류를 숨기지 않는다.
- 배경 바닥 재질은 맵별 선택 참조다. 비어 있으면 Resources의 `IBIIIS/DefaultGround` 재질을 사용한다. 이동 영역과 환경은 자동 연동하지 않는다. 기본 에셋 생성기는 기존 에셋을 덮어쓰지 않는다.
- 저장한 맵은 테스트 씬의 `GridMapPlayer.map`에서 참조한다. 실행 시 `GridSession`이 이동 가능 정보·시작 위치·적 규칙을 복사하고 실행 상태를 별도로 관리한다. 실행 중 원본 수정은 다음 시작 시 반영된다.
- Scene 미리보기는 맵·타일 에셋을 읽어 임시 외형만 생성한다. 생성 오브젝트·임시 머티리얼은 저장 제외이며 런타임 세션을 생성하지 않는다.
- 실제 편집·저장·테스트 씬 생성 절차와 검증 결과는 [개발 및 사용 가이드](IBIIIS_개발_및_사용_가이드.md)에, 적 배치 절차는 [전투 및 적 배치 가이드](IBIIIS_전투_및_적배치_가이드.md)에 있다.

## 적 프리팹 데이터

`EnemyDefinition`이 적 프리팹 루트에서 Enemy Id, 행동 목록, 인식·공격·인식 후 공격 범위, 편집기 색상, 카메라를 향할 `Visual` 참조를 관리한다. 행동 목록이 비어 있는 이전 프리팹은 숨은 `moveCells` 값으로 동작하며 Inspector에서 행동 목록으로 변환할 수 있다. GridMap은 프리팹 참조만 저장하므로 프리팹을 수정하면 그 적을 배치한 모든 맵에 반영된다. Excel·HTML·Word 자료는 참고 규칙이며 자동 가져오기는 없다. 편집 항목은 [전투 및 적 배치 가이드](IBIIIS_전투_및_적배치_가이드.md)를 따른다.

## 공용 설정 에셋

| 에셋 | 관리 항목 |
|---|---|
| `Assets/IBIIIS/Settings/GlobalPlayerSettings.asset` | 플레이어 외형 프리팹, 한 칸 이동 시간(초), 적 한 칸 이동 시간(초), 이동 가능 칸 표시 여부·색상·재질, 적 범위 표시 시작값, 입력·충돌 연출 설정 연결 |
| `Assets/IBIIIS/Settings/GlobalCameraSettings.asset` | 카메라 Projection·회전·화각. 맵 에셋에는 카메라 설정을 저장하지 않는다 |
| `Assets/IBIIIS/Settings/IBIIISInput.inputactions` | 전투 키 배치(`Battle` 액션 맵) |
| `Assets/IBIIIS/Settings/CollisionFeedback.asset` | 충돌·패배 연출의 시간·강도·이펙트·효과음 |
| `Assets/IBIIIS/Settings/EnemyAlert.asset` | 적 인식 표시(!·?) 그림·높이·크기·튀어나옴·효과음 |
| `Assets/IBIIIS/Settings/OverworldSettings.asset` | 미니맵 이동 속도, 카메라 설정 연결·보이는 세로 범위·따라가는 빠르기, 달리기 속도·보폭, 구르기 거리·시간·감속·회복·쿨다운, 걷기 손맛, 미니맵 입력 연결 |
| `Assets/IBIIIS/Settings/OverworldCameraSettings.asset` | 미니맵 전용 카메라 각도·화각(현재 회전 40°, 화각 30). 전투의 GlobalCameraSettings와 별개 |
| `Assets/IBIIIS/Settings/OverworldInput.inputactions` | 미니맵 키 배치(`Overworld` 액션 맵: Move, Interact, Dash(누르고 있으면 달리기), Roll) |

이동 시간은 각 행동 시작 시 개별 세션에 복사하며 실행 상태는 공용 설정에 기록하지 않는다. 입력 에셋은 실행 시 사본을 만들어 쓴다. 편집 절차는 개발 및 사용 가이드를 따른다.

## 클리어 기록

- 위치: `Application.persistentDataPath/IBIIIS_progress.json`(Windows 에디터에서는 보통 `%USERPROFILE%\AppData\LocalLow\<회사 이름>\<제품 이름>\`). 메뉴 `IBIIIS > Overworld > Show Save File`로 연다.
- 형식: `{"version": 1, "clearedStages": ["스테이지 ID", ...]}`. 승리 시 해당 스테이지 ID를 한 번만 추가하고 바로 저장한다. 임시 파일에 쓴 뒤 교체한다.
- 키는 `StageEntrance`의 Stage Id다. 표시 이름·씬 경로가 바뀌어도 ID가 같으면 기록이 유지된다. ID를 바꾸거나 두 입구에 같은 ID를 쓰면 기록이 어긋나므로 Inspector가 누락·중복을 알린다. ID 명명 규칙은 미정이다.
- 읽을 수 없는 파일은 `.corrupt` 사본으로 보존한 뒤 빈 기록으로 시작한다. 더 새로운 버전의 파일도 같은 방식으로 다룬다.
- 초기화는 `IBIIIS > Overworld > Reset Clear Records`(파일 삭제). 저장 슬롯·클라우드 저장은 없다.

## 환경 배치 데이터

맵별 환경 배치는 `GridMap.environmentPrefab`이 참조하는 프리팹에서 관리한다. Scene에는 연결된 인스턴스와 인스턴스/원본 참조를 저장한다. Scene override는 해당 씬에만 적용되고, 다른 테스트 씬으로 전파하려면 환경 프리팹에 적용해야 한다. 타일 자동 생성은 환경 인스턴스를 변경하지 않는다. 환경 교체·해제 시 미적용 변경이 있으면 편집 동기화를 보류한다. 외형의 배치·Collider는 격자 이동 데이터로 가져오지 않는다.

## 데이터 작성 기준

- 적 ID와 패턴 ID는 각각 중복 없는 식별자로 관리한다. 이름이 바뀌어도 같은 콘텐츠의 ID를 임의로 바꾸지 않는다.
- 적 기본정보의 패턴 ID는 행동 패턴 시트의 패턴 ID를 참조한다.
- ID 접두사·번호 규칙과 삭제된 ID의 재사용 정책은 미정이다.
- 체력과 행동 주기는 숫자로 기록한다. 미정은 빈칸으로 두고 0으로 대체하지 않는다. 정확한 허용 범위는 규칙 확정 시 정의한다. 행동 주기를 현재 시간 규칙에 맞게 표현하는 방식은 미정이다.
- 이동·공격·타깃 규칙은 현재 기획 문장이다. 구조화된 실행 데이터로 자동 해석할 수 있다고 가정하지 않는다.
- 인식범위는 공격범위와 구분한다. 엑셀에서 인식범위를 표기하는 형식은 미정이다.
- 기획 상태의 선택값은 초안, 검토 중, 확정이다. 기획 확정은 구현 완료나 게임 반영 완료를 의미하지 않는다.

## 가져오기 도입 시 결정할 항목 — 현재 사용 불가

| 항목 | 결정·기록할 내용 |
|---|---|
| 입력 형식 | XLSX 직접 처리 또는 별도 변환 형식 |
| 필드 대응 | 시트·열과 런타임 필드의 매핑, 자료형·단위 |
| 관리 권한 | 가져오기로 덮어쓸 값과 Unity에서 보존할 값 |
| 검증 | 중복 ID, 누락 참조, 빈칸, 범위 밖 수치의 처리 |
| 반영 방식 | 변경 미리보기, 신규·수정·삭제 처리, 실행 중 반영 여부 |
| 실패 처리 | 사전 검증, 부분 반영 방지, 복구 방법 |
| 구조 변경 | 스키마 버전, 필드 변경과 기존 데이터 이전 |

외형·연출 참조는 별도 매핑을 명시적으로 설계하기 전까지 가져오기 대상으로 삼지 않는다. 실제 가져오기 도구가 구현되면 위 표를 구체화하고 사용 절차는 [개발 및 사용 가이드](IBIIIS_개발_및_사용_가이드.md)에 연결한다.
