# IBIIIS 개발 및 사용 가이드

작성일: 2026-10-01 · 갱신일: 2026-10-05 · 버전: 0.4 · 상태: 맵 편집·Scene 미리보기·기본 이동 구현, 플레이 사용자 확인 대기

## 최신 전투·적 배치 변경 — 2026-10-05

플레이어와 적이 동시에 이동을 시작하며 양쪽 이동 완료 후 공격·피격을 처리한다. 적끼리 충돌은 한 칸 도착마다 처리한다. 맵 에디터의 적 프리팹 선택·방향·배치·삭제 및 조작은 [전투 및 적 배치 가이드](IBIIIS_전투_및_적배치_가이드.md)를 따른다. 아래 이전 날짜의 적 미구현·플레이어 도착 즉시 정지 설명은 이 최신 절차로 대체한다. 맵은 사용자가 제작하며 기존 맵을 자동 수정하지 않았다.

## 용도와 확인 범위

프로젝트를 실행하고, 외형을 교체하고, 적과 오브젝트를 추가하는 실제 절차를 기록한다. 개발 시에는 구현 구조와 새 기능의 연결 지점을 확인하는 데 사용한다.

맵 편집기와 기본 이동 프로토타입을 구현했다. 아래 전용 절차에 구현 범위와 검증 결과를 기록한다. 적·회피기·전투 등 예정 항목은 아직 사용할 수 있는 기능으로 해석하지 않는다.

## 검증 역할

실제 게임을 직접 조작하는 플레이 검증은 사용자가 담당한다. 에이전트는 컴파일·정적 검사·데이터 및 참조 검사·자동 테스트 등 개발 검증을 수행하고, 사용자가 확인할 씬과 설정, 조작 순서, 기대 결과를 전달한다. 구체적인 작업 원칙은 [AGENTS.md](../AGENTS.md)의 검증과 완료 보고를 따른다.

기능별 기록은 개발 검증 결과와 사용자 플레이 검증 결과를 나누어 작성한다. 사용자가 확인하기 전에는 플레이 검증을 '사용자 확인 대기'로 표시하고, 피드백을 받으면 확인한 범위와 남은 문제를 기록한다.

## 맵 편집·기본 이동 프로토타입

### 시작과 편집

1. Unity `6000.3.23f1`에서 프로젝트를 연다. 메뉴 `IBIIIS > Map Editor`로 전용 창을 연다. Scene 창이나 Play 모드는 필요 없다.
2. 상단 맵 슬롯에 `Assets/IBIIIS/Maps/StarterMap/StarterMap.asset`을 넣는다. 샘플은 12×10칸이며 기존 배치와 시작 위치를 유지한다. 기존 장애물 칸은 사용자가 삭제했다. `IBIIIS > Create Starter Map`은 기존 샘플을 덮어쓰지 않고 연다.
3. `새 맵`에서 이름과 저장 위치를 지정하면 같은 폴더에 `이름.asset`(GridMap)과 `이름.unity`(해당 맵을 연결한 씬)를 함께 생성한다. 둘 중 하나라도 같은 이름이 있으면 공통 이름에 번호를 붙여 기존 파일을 보존한다. 기본 크기는 12×12이고 모든 칸이 비어 있다. 시작 위치도 아직 없으므로 편집용 씬만 생성하고, Play 전에는 바닥과 시작 위치를 지정해야 한다. 씬에는 공용 플레이어·카메라 설정과 기본 머티리얼을 자동 연결한다. 생성된 씬은 Project에서 선택되며 더블클릭해 연다. 현재 열린 씬을 자동으로 교체하지 않는다. 이름 없는 씬이 열려 있으면 먼저 저장하라는 안내가 나오며 맵만 생성하지 않는다. 씬 생성 실패 시 이번에 만든 맵·씬을 정리한다.
4. 왼쪽 도구 레일에서 `칠하기 B`를 선택하고 클릭·드래그한다. `지우기 E`는 이동 영역만 제거하고 배경 바닥은 남긴다. 빈칸은 이동 불가다. 드래그 한 번은 Undo 한 번으로 복구한다. 하단 `칠하기` 탭의 바닥 견본에서 종류를 선택해 칠한다. 이동 불가 타일은 등록·배치할 수 없다.
5. `시작 위치` 도구로 이동 가능한 칸을 클릭한다. 노란 테두리가 시작 위치다. 시작 칸을 지우면 시작 위치도 해제되고 재지정 안내가 나온다. 다시 칠하기만 해서는 시작 위치가 복원되지 않는다. 잘못된 시작 위치는 플레이 준비 검증에서 거부한다.
6. 가운데 버튼 드래그로 화면 이동, 휠로 확대·축소, 오른쪽 클릭(또는 `선택 V` 도구)으로 칸을 선택해 하단 `선택한 칸`에서 정보를 본다. `화면 맞춤`(F)은 맵 전체가 보이게 맞춘다. 격자 위쪽은 +Y이며 런타임의 +Z와 대응한다.
7. 가로·세로를 1~64칸으로 입력하고 `크기 적용`을 누른다. 좌하단 (0,0)을 기준으로 기존 칸을 유지한다. 축소 전에 경고하고, 범위 밖 시작 위치는 해제한다. 실행 취소로 복구 가능하다.
8. `저장`으로 맵 에셋을 저장한다. Unity의 프로젝트 저장도 변경된 에셋을 저장할 수 있으므로 이 창을 별도의 미저장 초안 편집기로 해석하지 않는다. 저장 후에도 Undo를 하면 다시 저장해야 한다.

### 맵 에디터 화면 구성 — 2026-10-06

- **위 도구줄**: 맵 선택, `새 맵`, `저장`(저장 전 변경이 있으면 `저장 *`), 실행 취소/다시 실행, `모든 적 범위` 토글, `화면 맞춤`.
- **왼쪽 도구 레일**: `칠하기 B`, `지우기 E`, `시작 위치 S`, `적 배치 N`, `적 지우기 X`, `선택 V`. 현재 도구가 강조된다. 단축키는 캔버스나 도구 버튼을 클릭해 창에 초점이 있을 때 동작하고, 숫자·이름 입력 칸에 입력 중일 때는 무시된다. `R`은 적 배치 방향(선택 도구로 적을 고른 상태면 그 적)을 시계 방향으로, `Shift+R`은 반시계로 돌린다. `Delete`/`Backspace`는 선택한 적을 지우고, `F`는 화면 맞춤, `Esc`는 선택 해제다.
- **캔버스**: 마우스 아래 칸에 현재 도구의 결과를 미리 보여 준다(칠할 바닥 색, 지울 칸의 X, 시작 위치 테두리, 놓을 적과 방향). 적용할 수 없는 칸(시작 위치·이동 불가 칸에 적 배치 등)은 빨간 테두리로 표시한다. 마우스를 올리거나 선택한 적의 범위를 게임과 같은 색으로 보여 준다(노란 테두리=인식, 빨간 칸=공격, 빨간 테두리=인식 후에만 추가되는 공격, 이동 가능한 칸만 표시). `모든 적 범위`를 켜면 전체 적의 범위를 함께 그린다. 선택한 칸은 하늘색 테두리다.
- **하단 패널**(캔버스 아래, 경계선을 끌어 높이 조절): 왼쪽 `선택한 칸`에 좌표·바닥·시작 위치·적(이름·방향·행동 목록)을 표시하고, 적이면 `왼쪽 회전`·`오른쪽 회전`·`적 삭제` 버튼이 나온다. 오른쪽 탭은 `칠하기`(바닥 견본·새 바닥·바닥 설정), `적`(적 타일 팔레트, 배치 방향 4버튼, 선택한 적 요약), `맵`(크기, 배경, 환경 설정, 조작 방법), `검증`이다. `칠하기`·`적 배치` 도구를 고르면 해당 탭으로 바뀐다.
- **아래 상태 표시줄**: 저장 상태, 크기, 적 수(홀수 표시), 플레이 준비/확인 필요 항목, 마우스 아래 칸 정보, 최근 메시지.
- **적 타일 팔레트**: 프로젝트의 모든 프리팹 중 루트에 EnemyDefinition이 있는 것을 자동으로 찾아 바닥 견본처럼 타일로 보여 준다(이름순). 타일에는 프리팹 안 SpriteRenderer의 스프라이트(없으면 Editor Color 사각형)와 위쪽 Editor Color 띠가 표시되고, 마우스를 올리면 경로와 행동 목록이 나온다. 클릭하면 선택되고 `적 배치` 도구로 바뀐다. 설정이 올바르지 않은 적은 흐리게 표시되며 선택할 수 없다. 새 적 프리팹을 만들거나 지우면 목록이 자동으로 갱신된다. 이전의 `적 프리팹` 오브젝트 슬롯은 제거했다.

### 평면 바닥과 이동 영역 — 2026-10-03

- 맵 에디터 `맵` 탭의 `배경과 기본 바닥` 또는 GridMap Inspector에서 `배경 바닥 재질`을 지정한다. 비우면 `Assets/IBIIIS/Resources/IBIIIS/DefaultGround.mat`을 사용한다. 이 공용 기본 재질을 수정하면 별도 재질을 지정하지 않은 맵에 함께 적용된다.
- 배경 바닥은 XZ 평면 Y=0, 이동 영역은 Y=0.01에 생성한다. 타일 입체 외형은 사용하지 않는다. 맵 (0,0)은 두 평면과 환경의 공통 기준점이다.
- `외곽 여유 (칸)`의 기본값은 각 방향 50칸이며 맵별 수정 가능하다. 바닥의 크기는 그리드 크기 + 양쪽 여유다. 무한 바닥이 아니므로 카메라에 끝이 보이면 여유를 늘린다. 카메라는 배경 바닥 크기와 무관하게 그리드 범위를 기준으로 맞춘다.
- `기본 바닥 색상`은 종류를 지정하지 않은 바닥의 표시 설정이며 현재 Scene과 Play 모두 표시한다. 최종 표시 정책은 미정이다.
- 바닥과 이동 영역은 자동 생성·재생성되므로 직접 편집하지 않고 맵 설정에서 수정한다. 수동 환경 인스턴스는 별도 관리하며 재생성 시 보존한다.
- 환경 오브젝트 자동 점유는 추가하지 않았다. 현 구현에서는 통행을 막으려는 칸을 직접 지워야 한다. 부분 점유·자동화 정책은 미정이다.
- 기존 맵의 셀 ID·팔레트 참조는 호환용으로 보존한다. 기존 이동 가능 칸은 평면 외형으로 표시하며, 종류 없는 기본 바닥도 계속 사용 가능하다. 기존 TileDefinition과 GUID는 삭제하지 않는다.
- 확인 순서: 새 맵과 씬 생성 → 이동 영역과 시작 위치 지정 → 씬 열기 → 바닥 재질 교체 → 시작 칸 삭제·Undo → Play 이동 확인. 빈칸에서는 바닥만 보이며 이동할 수 없어야 한다. 화면 및 직접 플레이 확인은 사용자 확인 대기다.
### 여러 종류의 이동 바닥

1. 맵을 선택하고 `새 바닥 만들기`를 누른다. 예를 들어 Grass, Stone, Dirt 이름으로 에셋을 각각 생성한다. 생성한 바닥은 현재 맵 팔레트에 등록되고 선택된다. 예시 종류를 자동 생성하거나 기존 맵에 칠하지는 않는다.
2. 선택한 바닥 아래에서 `바닥 이름`, `표시 색상`, `바닥 재질`을 편집한다. 재질은 선택 사항이다. 맵 에디터는 표시 색상을 사용하고 Scene/Play는 지정된 재질을 그대로 사용한다. 재질이 없으면 표시 색상으로 표시한다. 재질의 색상에 표시 색상을 곱하지 않는다.
3. 팔레트의 바닥 버튼을 선택한 뒤 격자를 클릭·드래그한다. 기존 바닥을 다른 종류로 덧칠해도 이동 가능 여부와 시작 위치는 유지된다. `지우기`는 종류와 무관하게 이동 영역을 지우며 시작 칸을 지우면 시작 위치도 해제한다.
4. 다른 맵의 바닥 에셋은 `기존 바닥`에 넣고 `팔레트에 등록`한다. 같은 바닥 에셋의 외형 변경은 그 바닥을 사용하는 모든 맵에 적용된다. 서로 독립적인 외형이 필요하면 `새 바닥 만들기`로 생성한다. Project 단순 복제는 ID가 중복되므로 등록을 거부한다.
5. `기본 바닥`을 선택하면 별도 에셋 없이 기존 방식으로 칠한다. 배경 바닥 재질과 이동 바닥 종류는 별도 설정이다. `저장`은 맵과 팔레트 바닥 설정을 저장한다.
6. 사용자 확인: 서로 다른 바닥 두 종류를 인접 배치 → Scene/Play의 재질 차이 확인 → 두 칸 모두 이동 가능 확인 → 덧칠·Undo·지우기 확인. 실제 화면과 직접 플레이는 사용자 확인 대기다.
### 사용자 플레이 확인

1. 샘플은 `Assets/IBIIIS/Maps/StarterMap/StarterMap_Test.unity`를 연다. 새 맵은 함께 생성된 같은 이름의 `.unity` 씬을 연다. 상단의 `테스트 씬 만들기` 버튼은 제거했다. 기존 열린 씬은 새 맵 생성 과정에서 덮어쓰거나 저장하지 않는다.
2. 테스트 씬의 `Grid Map Player` 오브젝트에서 Map, Cell Size, Player Settings 연결을 확인한다. 플레이어 외형·이동 시간은 아래 공용 플레이어 설정에서 수정한다. 기본 임시 규칙은 [기획서](IBIIIS_게임시스템_기획서.md)에 있다.
3. Play 후 Game 창을 클릭하고 WASD를 누른다. W/S는 격자 +Y/-Y, A/D는 -X/+X다. 화면상 방향은 카메라 구도에 따라 달라진다. 한 번 누를 때 한 칸 이동하고, 동시에 여러 키를 누르면 W→S→A→D 중 하나만 처리한다. 키를 계속 누르고 있어도 반복 이동하지 않는다.
4. 대기 중에는 게임 시간이 정지하고, 유효한 이동 입력 시 설정된 시간 동안 한 칸을 보간 이동하며 게임 시간이 흐른다. 도착 후 적 행동·판정을 처리하고 다시 정지한다. 빈칸·경계 입력과 이동 중 추가 입력은 무시한다. 화면 왼쪽 위에는 Moving/Waiting과 도착 완료 좌표가 표시된다.
5. Play 종료 후 시작 위치와 저장한 타일 배치가 유지되는지 확인한다. 외형 프리팹의 크기를 바꿔도 이동 가능 칸이 달라지지 않아야 한다.
6. 맵을 편집한 뒤 저장하고 다시 Play하면 변경이 반영된다. 실행 중에는 맵 편집 창을 비활성화한다. 실행 상태에는 시작 시점의 이동 가능 정보를 복사한다.

### Scene에서 맵과 카메라 확인

1. `StarterMap_Test.unity`처럼 Grid Map Player가 연결된 씬을 열면 Play 전에도 바닥·장애물·플레이어 시작 외형이 자동 표시된다. 전용 맵 에디터에서 배치를 바꾸거나 타일 Inspector에서 색상·외형을 바꾸면 약 0.4초 간격으로 갱신한다. Scene의 개별 생성 오브젝트를 편집하지 않고 맵 에셋에서 배치를 수정한다.
2. `Grid Map Player` Inspector의 `Auto Fit Camera`는 기본 켜짐이다. Scene과 Play에 같은 카메라 구도 계산을 적용한다. Camera Settings가 연결되어 있으면 공용 설정의 Projection·회전·화각을 사용한다. 없으면 Camera의 현재 Projection·회전·화각을 유지하며 맵 전체를 맞춘다.
3. 직접 구도를 잡으려면 `Auto Fit Camera`를 끄고 연결된 `Map Camera`의 위치·회전·Projection·Size/FOV를 편집한다. Play에서 해당 설정을 덮어쓰지 않는다. `카메라를 맵 전체에 맞추기`는 자동 맞춤을 끈 상태에서도 한 번 맞추는 버튼이다.
4. `Scene 뷰를 게임 카메라 방향으로 보기`로 Scene 뷰의 방향을 맞춘다. Scene 뷰와 Game 뷰의 종횡비가 다를 수 있으므로 정확한 화면 테두리는 Map Camera 선택 시 Camera Preview 또는 Play 전 Game 뷰에서 확인한다. Perspective 수동 구도에서는 Scene 버튼이 동일한 프레이밍까지 보장하지 않는다.
5. 외형이 갱신되지 않으면 `Scene 미리보기 새로고침`을 누른다. 미리보기는 Hierarchy에 숨겨진 저장 제외 오브젝트다. 씬 저장·빌드 대상에 포함되지 않으며 씬을 다시 열 때 재생성한다. 컴포넌트 비활성화·삭제·스크립트 리로드·Play 진입 시 정리한다.
6. 미리보기에서는 입력·시간 진행와 실행 세션을 시작하지 않는다. 시작 위치가 미지정이어도 유효한 맵 타일은 표시하며 플레이어 표식만 생략한다. 타일 ID·참조 오류가 있는 맵은 미리보기를 제거하므로 맵 에디터의 오류 표시를 확인한다.
7. Prefab Mode와 Unity 내부 Preview Scene에서는 자동 생성을 하지 않는다. 런타임 HUD(이동/대기 상태·현재 좌표)는 Play 전에는 표시하지 않는다. 임시 외형 표시는 실행과 공통 생성 코드를 사용한다.

추가 코드: `Assets/IBIIIS/Editor/GridMapPreview.cs`가 자동 갱신·정리와 Grid Map Player Inspector를 담당한다. `GridMapPlayer.cs`의 공통 외형 생성·카메라 맞춤을 편집 미리보기와 실행에서 재사용한다. 맵이나 공유 타일 설정 원본은 미리보기가 수정하지 않는다.

### 공용 카메라 설정 — 2026-10-02

- `Assets/IBIIIS/Settings/GlobalCameraSettings.asset`을 선택해 Inspector에서 편집한다. Orthographic 끔 = Perspective, Rotation = `(55, 0, 0)`, Field Of View = `60`이 현재 값이다. 정면은 좌우 회전 Y=0을 의미하며, 바닥을 볼 수 있도록 내려다보는 X=55°를 유지했다.
- 현재 `StarterMap_Test.unity`와 앞으로 생성하는 테스트 씬은 이 에셋을 참조한다. 별도로 만든 기존 씬은 Grid Map Player의 Camera Settings에 같은 에셋을 연결하고 Auto Fit Camera를 켜면 함께 적용된다.
- Perspective에서는 맵 크기·화각·화면 비율에 따라 거리를, Orthographic에서는 Size를 계산한다. 그리드 범위와 플레이어 표시 높이를 포함하며 임의로 매우 크게 만든 외형까지 자동으로 맞추지는 않는다.
- Auto Fit Camera를 끄면 씬 Camera의 개별 설정을 유지한다. 공용 값은 설정 에셋에, 설정 참조와 개별 카메라 값은 씬에 저장한다.
- 현재 씬의 기존 변경을 유지한 채 설정 연결과 카메라를 저장했다. Unity 컴파일 완료 및 실제 Camera의 Perspective·회전·FOV 적용 확인. 가로·세로 화면의 맵 포함 검사 테스트를 추가하고 전체 테스트 실행을 요청했으나, 최종 결과 조회가 사용자에 의해 거절되어 이번 변경 후 테스트 완료 결과는 미확인이다. 실제 플레이 구도는 사용자 확인 대기다.

## 공용 플레이어 설정 — 2026-10-03

1. `IBIIIS > Player Settings` 또는 `Assets/IBIIIS/Settings/GlobalPlayerSettings.asset`을 연다. 같은 설정을 사용하는 씬 전체에 적용된다.
2. `Visual Prefab`은 기존 외형 슬롯이다. 이번 이동 모션은 위치 보간이며 전용 걷기 애니메이션 클립·Animator 상태 전환은 추가하지 않았다.
3. `Move Duration`은 한 칸 이동 시간(초), 임시 기본값 0.25, 최소 0.01이다. 매 이동 시작 시 읽으므로 진행 중인 이동은 기존 시간을 유지하고 다음 이동부터 변경된다. 턴 카운터·정상/막힌 이동 비용은 제거했다.
4. `Show Move Hints`로 표시를 켜고 끈다. `Move Hint Color`는 이동 가능한 상하좌우 칸, `Destination Color`는 이동 중 목적지 색상이다. `Move Hint Material`은 선택 재질이며 표시용 사본을 사용한다. Scene 미리보기에도 시작 위치 기준의 이동 가능 칸이 표시된다. 표시 색상·재질·외형은 Play 재시작 시 반영한다.
   - 추가 설정: `Show Enemy Ranges`(기본 켬)는 Play 시작 시 적 인식·공격 범위 표시 여부이며 Play 중 Tab으로 전환한다. 되돌리기(Backspace/U)와 함께 [전투 및 적 배치 가이드](IBIIIS_전투_및_적배치_가이드.md)에 설명한다.
   - 추가 설정: `Input Actions`는 전투 키 배치 에셋이다. 비우면 코드의 기본 키 배치를 쓴다.
5. 대기 중에는 인접한 이동 가능 칸만 테두리를 표시한다. 이동 중에는 목적지만 표시하고 도착 후 새 위치 기준으로 갱신한다. 판정과 표시는 같은 이동 검사를 사용한다. 표시 높이는 Y=0.025, 타일은 Y=0.01이다.
6. 실제 게임에서는 `MovementWorldTime`이 `Time.timeScale`을 입력 대기·승패 0 / 플레이어·적 행동 1로 관리한다. 마지막 플레이어가 비활성화·제거되거나 Play를 종료할 때 이전 timeScale을 복구한다. 입력과 위치 보간은 정지 상태에서도 시작할 수 있다. 앞으로 게임 진행 요소는 `Time.deltaTime`, 일반 Animator/물리 등 스케일된 시간을 사용해야 한다. unscaled 시간·외부 타이머·오디오까지 자동 정지시키지는 않는다.
7. 도착 전 논리 좌표는 출발 칸에 유지하고 목적지를 별도로 보관한다. 설정 원본에 위치·진행률을 기록하지 않는다. 실행 맵 판정은 시작 시 복사한다. 중도 비활성화 시 이동은 취소되고 다시 활성화하면 맵 시작 위치에서 시작한다.
8. 확인 순서: 테스트 씬을 열고 이동 시간을 0.5초로 지정 → 인접 테두리 확인 → WASD 한 번 입력 → 목적지 테두리와 부드러운 이동 확인 → 도착 후 대기 확인. 이동 중 다른 방향 입력은 예약되지 않고, 막힌 방향 입력은 시간을 진행시키지 않아야 한다. 직접 플레이 확인은 사용자 확인 대기다.

공용 설정이 없는 옛 씬은 경고와 함께 기본 이동 시간 0.25초를 사용한다. 기존 숨겨진 플레이어 외형 참조는 유지하지만 턴 비용 필드는 제거했다. 글로벌 설정의 기존 외형 참조는 보존한다. 표시용 기본 색상은 청록색/노란색이다.

## Scene 환경 장식 배치 — 2026-10-02

### 만들기와 편집

1. 맵 에디터의 `환경 설정`을 누르거나 맵 에셋을 선택한다. Inspector의 `Environment Prefab`은 선택 슬롯이다. 비어 있어도 플레이할 수 있다.
2. `새 환경 프리팹 만들고 연결`을 누르고 저장 경로를 정한다. 빈 `Environment` 루트 프리팹을 생성한다. 기존 에셋을 덮어쓰지 않는다. 기존 환경 프리팹을 슬롯에 직접 연결할 수도 있다.
3. 해당 맵이 연결된 씬을 열면 `Grid Map Player` 아래에 환경 프리팹 인스턴스가 생성된다. `Scene 환경 선택` 버튼으로 선택할 수 있다. 자동 생성되어 숨겨진 타일 미리보기와 별개의 저장 가능한 오브젝트다.

   현재 샘플은 `Assets/IBIIIS/Environments/StarterMap_Environment.prefab`을 연결하고 `StarterMap_Test.unity`에 빈 환경 인스턴스를 저장했다. 장식 에셋은 사용자가 자식으로 배치한다.
4. Environment 아래에 장식 프리팹을 자식으로 배치하고 Unity 이동·회전·크기 도구로 편집한다. 맵 내부·외부 모두 허용한다. 환경 루트는 위치·회전 0, 크기 1을 유지하고 자식에서 보정한다. 원점은 맵 (0,0) 칸 중심, XZ는 바닥, Y는 높이다. Cell Size 변경은 장식 배치를 자동 확대·축소하지 않는다.
5. `Grid Map Player > 환경 배치를 프리팹에 적용` 또는 Unity의 Prefab Overrides 적용 기능으로 배치를 원본에 반영한다. 적용은 이 환경을 참조하는 다른 맵·씬에도 영향을 준다. 씬도 저장한다. 씬 저장만 한 변경은 해당 씬의 override이며 다른 테스트 씬에 전파되지 않는다.
6. 새 테스트 씬에는 맵에 연결된 환경 프리팹이 자동 배치·저장된다. 이름 없는 씬이 열려 있으면 먼저 사용자가 저장해야 한다. 생성기는 현재 씬을 임의로 저장하지 않는다.

### 교체와 변경 보호

- 타일 칠하기·지우기·크기 변경·Scene 미리보기 갱신은 환경 인스턴스를 삭제하거나 다시 만들지 않는다. 컴포넌트를 비활성화해도 환경 배치는 보존된다.
- 연결된 환경을 교체·해제했을 때 미적용 변경이 없으면 Scene을 동기화한다. 미적용 변경이 있거나 연결이 끊긴 인스턴스이면 기존 배치를 유지하고 Inspector에 변경 대기를 표시한다.
- `환경 연결 동기화 / 변경 해결`에서 `적용 후 교체`, `버리고 교체`, `취소`를 선택한다. 적용은 이전 환경 프리팹에 수행한다. 프리팹 연결이 끊긴 경우 Unity의 프리팹 저장 기능으로 먼저 별도 보존해야 한다.
- 루트 위치·회전·크기 변경도 보호 대상이다. 프리팹 적용 전 자식으로 보정을 옮기고 루트를 원래 기준으로 되돌린다. 루트가 기준과 다른 프리팹은 환경 슬롯에서 거부한다.
- Play 전에 연결 대기를 해결한다. Play에서는 맵에 지정된 환경을 사용하며, 저장된 인스턴스가 같은 환경이면 그대로 사용해 중복 생성하지 않는다. 다른 환경이면 실행 중 인스턴스만 교체하고 편집 상태는 Play 종료 시 복원된다.
- 환경 프리팹 변경은 Unity의 프리팹 갱신을 따른다. 기존 Scene override가 있는 항목은 원본 변경보다 우선할 수 있다.

### 판정과 검증 범위

- 환경은 장식 전용이다. Collider·크기·위치가 현재 격자 이동 판정을 바꾸지 않는다. 이동을 막으려면 맵 에디터의 이동 불가 타일을 별도로 지정한다. 여러 칸 점유·문·상자·파괴 기능은 미구현이다.
- 코드: `GridMap.environmentPrefab`, `GridMapPlayer`의 환경 인스턴스/소스 참조, `Assets/IBIIIS/Editor/MapEnvironmentEditor.cs`. 편집 환경은 Scene에 저장하고, 타일 미리보기와 별도로 유지한다.
- 사용자 확인: 환경 아래 소품 배치 → 타일 수정 후 위치 유지 확인 → 프리팹 적용 → 새 테스트 씬 생성 → 같은 배치 확인 → Play에서 환경 중복 생성 및 이동 판정 변화가 없는지 확인. 실제 Scene 배치 조작·화면·플레이는 **사용자 확인 대기**다.

## 플레이어 스프라이트 외형 — 2026-10-06

1. 원본: `Characters/Player/Sprites`(500×500 PNG 17장, 임시 러프 스케치). 외형 프리팹: `Characters/Player/PlayerVisual.prefab`, `GlobalPlayerSettings > Visual Prefab`에 연결됨. 메뉴 `IBIIIS > Create Default Player Visual`은 스프라이트 가져오기 설정(Sprite, PPU 500, Pivot 아래 중앙)을 맞추고, 프리팹이 없을 때만 만들며, 외형 슬롯이 비어 있을 때만 연결한다. 이미 있는 프리팹·연결은 덮어쓰지 않는다.
2. 프리팹의 `PlayerVisual`에서 대기·이동·대시(뒤/오른쪽/앞/왼쪽)와 구르기(뒤왼쪽·뒤오른쪽·앞왼쪽·앞오른쪽, First/Second) 슬롯의 스프라이트를 교체한다. 외형·표시 크기를 바꿔도 이동 가능 칸·판정은 변하지 않는다(표시 전용).
3. 방향은 카메라 Y 회전 0 기준 화면 방향이다: 격자 +Y=뒤(back), +X=오른쪽, -Y=앞(front), -X=왼쪽. 대기는 마지막 이동 방향을 유지한다. 구르기는 앞 절반에 First, 뒤 절반에 Second를 표시하고 이후 좌/우를 바라본다. 플레이어 표시는 Cell Size에 비례하고 카메라를 향한다. 크기는 프리팹의 `Sprite` 자식 Scale로 조정하며(현재 1.5, 사용자 확인 후 임시 확대) 발밑 기준점은 유지된다.
4. 임시 대체: 정면 대기, 뒤·앞 대시는 해당 그림이 없어 `c_basic_right`를 쓴다. 그림이 제작되면 `PlayerVisual`의 해당 슬롯만 교체한다. 슬롯이 비면 이전 표시를 유지하고 콘솔에 경고를 남긴다.
5. 자동 검증: Unity 컴파일 후 EditMode 43/43 통과(방향·동작별 선택, 구르기 프레임 전환, 빈 슬롯 경고, 카메라 정면 회전 포함). 실제 플레이 화면 확인은 사용자 확인 대기다.
6. 사용자 확인 순서: 테스트 씬을 열고 Play → WASD(이동 스프라이트), Shift+WASD(대시: 좌우만 전용, 앞뒤는 임시 그림), Q/E/Z/C(구르기 2프레임), 이동 후 대기 스프라이트가 마지막 방향인지, 캐릭터 크기·발밑 위치가 칸 중앙에 맞는지 확인한다.
