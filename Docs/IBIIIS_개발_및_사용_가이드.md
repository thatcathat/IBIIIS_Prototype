# IBIIIS 개발 및 사용 가이드

작성일: 2026-10-01 · 갱신일: 2026-10-02 · 버전: 0.4 · 상태: 맵 편집·Scene 미리보기·기본 이동 구현, 플레이 사용자 확인 대기

## 용도와 확인 범위

프로젝트를 실행하고, 외형을 교체하고, 적과 오브젝트를 추가하는 실제 절차를 기록한다. 개발 시에는 구현 구조와 새 기능의 연결 지점을 확인하는 데 사용한다.

맵 편집기와 기본 이동 프로토타입을 구현했다. 아래 전용 절차에 구현 범위와 검증 결과를 기록한다. 적·회피기·전투 등 예정 항목은 아직 사용할 수 있는 기능으로 해석하지 않는다.

## 검증 역할

실제 게임을 직접 조작하는 플레이 검증은 사용자가 담당한다. 에이전트는 컴파일·정적 검사·데이터 및 참조 검사·자동 테스트 등 개발 검증을 수행하고, 사용자가 확인할 씬과 설정, 조작 순서, 기대 결과를 전달한다. 구체적인 작업 원칙은 [AGENTS.md](../AGENTS.md)의 검증과 완료 보고를 따른다.

기능별 기록은 개발 검증 결과와 사용자 플레이 검증 결과를 나누어 작성한다. 사용자가 확인하기 전에는 플레이 검증을 '사용자 확인 대기'로 표시하고, 피드백을 받으면 확인한 범위와 남은 문제를 기록한다.

## 기능별 설명 양식

새 기능을 실제로 구현했을 때 아래 내용을 하나의 절차로 작성한다.

1. 기능 이름과 구현·검증 상태
2. 필요한 에셋과 사전 조건
3. 열어야 할 씬·프리팹·설정의 정확한 프로젝트 상대 경로
4. 사용자가 조작할 메뉴·슬롯·수치와 순서
5. 적용 시점과 기대되는 화면·동작
6. 개발 검증 방법과 결과, 사용자 플레이 확인 절차·기대 결과·확인 상태
7. 알려진 제한, 오류 원인과 해결 방법

## 구조 기록

`Assets/IBIIIS/Runtime/GridMap.cs`가 맵 설정, `TileDefinition.cs`가 타일 설정, `GridSession.cs`가 실행 중 위치·턴 및 이동 판정, `GridMapPlayer.cs`가 입력·맵 생성·임시 표시를 담당한다. `Assets/IBIIIS/Editor/`의 MapEditorWindow, MapCanvas, MapEditorSetup과 UXML/USS가 편집기와 새 테스트 씬 생성을 담당한다. Editor 코드는 런타임과 별도 어셈블리에 있다.

게임 규칙은 [기획서](IBIIIS_게임시스템_기획서.md)를 참조하고, 수치의 관리 위치와 데이터 반영 절차는 [데이터 관리 문서](IBIIIS_데이터_관리_문서.md)를 참조한다.

## 맵 편집·기본 이동 프로토타입

### 시작과 편집

1. Unity `6000.3.23f1`에서 프로젝트를 연다. 메뉴 `IBIIIS > Map Editor`로 전용 창을 연다. Scene 창이나 Play 모드는 필요 없다.
2. 상단 맵 슬롯에 `Assets/IBIIIS/Content/StarterMap.asset`을 넣는다. 샘플은 12×10칸이며 바닥·장애물과 시작 위치가 있다. `IBIIIS > Create Starter Map`은 기존 샘플을 덮어쓰지 않고 연다.
3. `새 맵`에서 이름과 저장 위치를 지정하면 같은 폴더에 `이름.asset`(GridMap)과 `이름.unity`(해당 맵을 연결한 씬)를 함께 생성한다. 둘 중 하나라도 같은 이름이 있으면 공통 이름에 번호를 붙여 기존 파일을 보존한다. 기본 크기는 12×12이고 모든 칸이 비어 있다. 시작 위치도 아직 없으므로 편집용 씬만 생성하고, Play 전에는 바닥과 시작 위치를 지정해야 한다. 씬에는 공용 플레이어·카메라 설정과 기본 머티리얼을 자동 연결한다. 생성된 씬은 Project에서 선택되며 더블클릭해 연다. 현재 열린 씬을 자동으로 교체하지 않는다. 이름 없는 씬이 열려 있으면 먼저 저장하라는 안내가 나오며 맵만 생성하지 않는다. 씬 생성 실패 시 이번에 만든 맵·씬을 정리한다.
4. 왼쪽 팔레트에서 바닥 또는 장애물을 선택하고 격자를 왼쪽 클릭·드래그해 칠한다. 지우려면 왼쪽 도구 목록의 `지우기`를 선택하고 왼쪽 클릭·드래그한다. 도구 목록과 하단 현재 도구 표시로 모드를 확인한다. 한 번의 드래그는 한 번의 실행 취소로 복구한다. 도구 목록의 `칠하기` 또는 팔레트 타일 선택으로 칠하기에 돌아간다. 지운 칸은 이동 불가한 빈 공간이 되며, 타일 에셋 자체는 삭제되지 않는다. 시작 위치의 타일을 지웠다면 이동 가능한 칸에 시작 위치를 다시 지정해야 한다.
5. `시작 위치` 도구로 이동 가능한 칸을 클릭한다. 노란 테두리가 시작 위치, X 표시는 이동 불가 타일이다. 아래 상태에 시작 위치 누락·잘못된 참조가 표시된다. 오류가 있는 작업 중 맵도 저장할 수 있지만 테스트 씬 생성은 거부된다.
6. 가운데 버튼 드래그로 화면 이동, 휠로 확대·축소, 오른쪽 클릭으로 칸 좌표·설정을 확인한다. 격자 위쪽은 +Y이며 런타임의 +Z와 대응한다.
7. 가로·세로를 1~64칸으로 입력하고 `크기 적용`을 누른다. 좌하단 (0,0)을 기준으로 기존 칸을 유지한다. 축소 전에 경고하고, 범위 밖 시작 위치는 해제한다. 실행 취소로 복구 가능하다.
8. `저장`으로 맵 에셋을 저장한다. Unity의 프로젝트 저장도 변경된 에셋을 저장할 수 있으므로 이 창을 별도의 미저장 초안 편집기로 해석하지 않는다. 저장 후에도 Undo를 하면 다시 저장해야 한다.

### 타일과 외형 편집

- `새 타일 만들기`로 독립 ID의 타일 에셋을 만들거나 기존 타일을 `등록할 타일` 슬롯과 `팔레트에 등록` 버튼으로 추가한다.
- `선택 타일 설정 열기`로 Inspector에서 Display Name, Walkable, Color, Visual Prefab을 편집한다. Walkable과 외형은 별개다. 이동 불가 지정은 해당 타일을 쓰는 모든 칸에 적용된다. 같은 모양의 일부 칸만 막으려면 별도 타일을 생성한다.
- 타일을 Project에서 단순 복제하면 ID도 복제되므로 동일 맵에 등록 시 중복 오류가 난다. 별도 콘텐츠는 `새 타일 만들기`를 사용한다. 이미 배치한 타일의 ID는 변경하지 않는다.
- 맵 Inspector에는 `맵 에디터에서 열기`와 팔레트가 있다. 사용 중인 타일을 팔레트에서 제거하면 해당 셀이 누락 참조로 표시된다. 지우거나 원래 타일을 재등록하여 해결한다.
- 외형 연결 기준은 [에셋 제작 가이드](IBIIIS_에셋_제작_가이드.md)의 임시 프로토타입 항목을 따른다.

### 사용자 플레이 확인

1. 샘플은 `Assets/IBIIIS/Content/StarterMap_Test.unity`를 연다. 새 맵은 함께 생성된 같은 이름의 `.unity` 씬을 연다. 상단의 `테스트 씬 만들기` 버튼은 제거했다. 기존 열린 씬은 새 맵 생성 과정에서 덮어쓰거나 저장하지 않는다.
2. 테스트 씬의 `Grid Map Player` 오브젝트에서 Map, Cell Size, Player Settings 연결을 확인한다. 플레이어 외형·이동 비용은 아래 공용 플레이어 설정에서 수정한다. 기본 임시 규칙은 [기획서](IBIIIS_게임시스템_기획서.md)에 있다.
3. Play 후 Game 창을 클릭하고 WASD를 누른다. W/S는 격자 +Y/-Y, A/D는 -X/+X다. 쿼터뷰 화면의 대각선 방향과 대응한다. 한 번 누를 때 한 칸 이동하고, 동시에 여러 키를 누르면 W→S→A→D 중 하나만 처리한다. 키를 계속 누르고 있어도 반복 이동하지 않는다.
4. 정상 이동 시 턴 +1, 장애물·빈 칸·맵 경계에서는 위치·턴 유지, 입력이 없으면 턴 유지가 기대 결과다. 화면 왼쪽 위에 턴·좌표가 표시된다.
5. Play 종료 후 시작 위치와 저장한 타일 배치가 유지되는지 확인한다. 외형 프리팹의 크기를 바꿔도 이동 가능 칸이 달라지지 않아야 한다.
6. 맵을 편집한 뒤 저장하고 다시 Play하면 변경이 반영된다. 실행 중에는 맵 편집 창을 비활성화한다. 실행 상태에는 시작 시점의 이동 가능 정보를 복사한다.

### Scene에서 맵과 카메라 확인

1. `StarterMap_Test.unity`처럼 Grid Map Player가 연결된 씬을 열면 Play 전에도 바닥·장애물·플레이어 시작 외형이 자동 표시된다. 전용 맵 에디터에서 배치를 바꾸거나 타일 Inspector에서 색상·외형을 바꾸면 약 0.4초 간격으로 갱신한다. Scene의 개별 생성 오브젝트를 편집하지 않고 맵 에셋에서 배치를 수정한다.
2. `Grid Map Player` Inspector의 `Auto Fit Camera`는 기본 켜짐이다. Scene과 Play에 같은 카메라 구도 계산을 적용한다. Camera Settings가 연결되어 있으면 공용 설정의 Projection·회전·화각을 사용한다. 없으면 Camera의 현재 Projection·회전·화각을 유지하며 맵 전체를 맞춘다.
3. 직접 구도를 잡으려면 `Auto Fit Camera`를 끄고 연결된 `Map Camera`의 위치·회전·Projection·Size/FOV를 편집한다. Play에서 해당 설정을 덮어쓰지 않는다. `카메라를 맵 전체에 맞추기`는 자동 맞춤을 끈 상태에서도 한 번 맞추는 버튼이다.
4. `Scene 뷰를 게임 카메라 방향으로 보기`로 Scene 뷰의 방향을 맞춘다. Scene 뷰와 Game 뷰의 종횡비가 다를 수 있으므로 정확한 화면 테두리는 Map Camera 선택 시 Camera Preview 또는 Play 전 Game 뷰에서 확인한다. Perspective 수동 구도에서는 Scene 버튼이 동일한 프레이밍까지 보장하지 않는다.
5. 외형이 갱신되지 않으면 `Scene 미리보기 새로고침`을 누른다. 미리보기는 Hierarchy에 숨겨진 저장 제외 오브젝트다. 씬 저장·빌드 대상에 포함되지 않으며 씬을 다시 열 때 재생성한다. 컴포넌트 비활성화·삭제·스크립트 리로드·Play 진입 시 정리한다.
6. 미리보기에서는 입력·턴 처리와 실행 세션을 시작하지 않는다. 시작 위치가 미지정이어도 유효한 맵 타일은 표시하며 플레이어 표식만 생략한다. 타일 ID·참조 오류가 있는 맵은 미리보기를 제거하므로 맵 에디터의 오류 표시를 확인한다.
7. Prefab Mode와 Unity 내부 Preview Scene에서는 자동 생성을 하지 않는다. 런타임 HUD(턴·현재 좌표)는 Play 전에는 표시하지 않는다. 임시 외형 표시는 실행과 공통 생성 코드를 사용한다.

추가 코드: `Assets/IBIIIS/Editor/GridMapPreview.cs`가 자동 갱신·정리와 Grid Map Player Inspector를 담당한다. `GridMapPlayer.cs`의 공통 외형 생성·카메라 맞춤을 편집 미리보기와 실행에서 재사용한다. 맵이나 공유 타일 설정 원본은 미리보기가 수정하지 않는다.

### 공용 카메라 설정 — 2026-10-02

- `Assets/IBIIIS/Content/GlobalCameraSettings.asset`을 선택해 Inspector에서 편집한다. Orthographic 끔 = Perspective, Rotation = `(55, 0, 0)`, Field Of View = `60`이 현재 값이다. 정면은 좌우 회전 Y=0을 의미하며, 바닥을 볼 수 있도록 내려다보는 X=55°를 유지했다.
- 현재 `StarterMap_Test.unity`와 앞으로 생성하는 테스트 씬은 이 에셋을 참조한다. 별도로 만든 기존 씬은 Grid Map Player의 Camera Settings에 같은 에셋을 연결하고 Auto Fit Camera를 켜면 함께 적용된다.
- Perspective에서는 맵 크기·화각·화면 비율에 따라 거리를, Orthographic에서는 Size를 계산한다. 기본 바닥·장애물 높이를 포함하며 임의로 매우 크게 만든 외형까지 자동으로 맞추지는 않는다.

## 공용 플레이어 설정 — 2026-10-02

1. 메뉴 `IBIIIS > Player Settings` 또는 `Assets/IBIIIS/Content/GlobalPlayerSettings.asset`을 연다. 씬의 Grid Map Player에 있는 `연결된 공용 플레이어 설정 열기` 버튼으로도 접근할 수 있다.
2. Inspector의 `Visual Prefab`에 플레이어 외형 프리팹을 연결한다. 같은 설정을 사용하는 모든 맵이 이를 사용한다. 빈 슬롯은 임시 노란 표식을 뜻한다. 스프라이트·크기·위치 보정은 프리팹에서 편집한다. 애니메이션·효과음 시스템은 아직 미구현이다.
3. `Move Turn Cost`는 1 이상, `Blocked Turn Cost`는 0 이상이다. 임시 규칙의 수치를 설정 에셋 한 곳에서 편집하고 저장한다. 이동 거리나 키 입력 방식은 이번 설정에 포함하지 않는다.
4. Scene 미리보기 외형은 설정 변경을 자동 감지한다. 실행 중에는 시작 시점의 외형과 이동 비용을 사용하며, 변경 사항은 다음 실행에 반영된다. 현재 위치·턴은 설정 에셋에 저장하지 않는다.
5. `StarterMap_Test.unity`는 기존 값(1/0, 외형 없음)을 옮긴 공용 에셋에 연결했다. 새 테스트 씬 생성기는 같은 에셋을 자동 연결하며 기존 공용 값을 덮어쓰지 않는다. 수동으로 만든 씬에서는 `Player Settings` 슬롯에 이 에셋을 연결한다.
6. 기존 직렬화 필드 `moveTurnCost`, `blockedTurnCost`, `playerVisualPrefab`은 데이터 보존을 위해 숨겨진 상태로 유지한다. 공용 에셋이 연결되어 있으면 사용하지 않는다. 미연결인 이전 씬은 경고와 함께 기존 값을 사용한다. 공용 슬롯의 빈 외형을 기존 외형으로 임의 대체하지 않는다.
7. 확인 절차: 공용 외형을 연결한 뒤 Scene 표시를 확인하고 Play에서 한 칸 이동·막힌 이동 비용을 확인한다. 두 테스트 씬이 같은 설정을 참조하는지도 확인한다. 화면 및 실제 플레이는 **사용자 확인 대기**다.

## Scene 환경 장식 배치 — 2026-10-02

### 만들기와 편집

1. 맵 에디터의 `환경 설정`을 누르거나 맵 에셋을 선택한다. Inspector의 `Environment Prefab`은 선택 슬롯이다. 비어 있어도 플레이할 수 있다.
2. `새 환경 프리팹 만들고 연결`을 누르고 저장 경로를 정한다. 빈 `Environment` 루트 프리팹을 생성한다. 기존 에셋을 덮어쓰지 않는다. 기존 환경 프리팹을 슬롯에 직접 연결할 수도 있다.
3. 해당 맵이 연결된 씬을 열면 `Grid Map Player` 아래에 환경 프리팹 인스턴스가 생성된다. `Scene 환경 선택` 버튼으로 선택할 수 있다. 자동 생성되어 숨겨진 타일 미리보기와 별개의 저장 가능한 오브젝트다.

   현재 샘플은 `Assets/IBIIIS/Content/StarterMap_Environment.prefab`을 연결하고 `StarterMap_Test.unity`에 빈 환경 인스턴스를 저장했다. 장식 에셋은 사용자가 자식으로 배치한다.
4. Environment 아래에 장식 프리팹을 자식으로 배치하고 Unity 이동·회전·크기 도구로 편집한다. 맵 내부·외부 모두 허용한다. 환경 루트는 위치·회전 0, 크기 1을 유지하고 자식에서 보정한다. 원점은 맵 (0,0) 칸 중심, XZ는 바닥, Y는 높이다. Cell Size 변경은 장식 배치를 자동 확대·축소하지 않는다.
5. `Grid Map Player > 환경 배치를 프리팹에 적용` 또는 Unity의 Prefab Overrides 적용 기능으로 배치를 원본에 반영한다. 적용은 이 환경을 참조하는 다른 맵·씬에도 영향을 준다. 씬도 저장한다. 씬 저장만 한 변경은 해당 씬의 override이며 다른 테스트 씬에 전파되지 않는다.
6. 새 테스트 씬에는 맵에 연결된 환경 프리팹이 자동 배치·저장된다. 이름 없는 씬이 열려 있으면 먼저 사용자가 저장해야 한다. 생성기는 현재 씬을 임의로 저장하지 않는다.

### 교체와 변경 보호

- 타일 칠하기·지우기·크기 변경·Scene 미리보기 갱신은 환경 인스턴스를 삭제하거나 다시 만들지 않는다. 컴포넌트를 비활성화해도 환경 배치는 보존된다.
- 연결된 환경을 교체·해제했을 때 미적용 변경이 없으면 Scene을 동기화한다. 미적용 변경이 있거나 연결이 끊긴 인스턴스이면 기존 배치를 유지하고 Inspector에 변경 대기를 표시한다.
- `환경 연결 동기화 / 변경 해결`에서 `적용 후 교체`, `버리고 교체`, `취소`를 선택한다. 적용은 이전 환경 프리팹에 수행한다. 프리팹 연결이 끊긴 경우 Unity의 프리팹 저장 기능으로 먼저 별도 보존해야 한다.
- 루트 위치·회전·크기 변경도 보호 대상이다. 프리팹 적용 전 자식으로 보정을 옮기고 루트를 원래 기준으로 되돌린다. 루트가 기준과 다른 프리팹은 환경 슬롯에서 거부한다.
- Play 전에 연결 대기를 해결한다. Play에서는 맵에 지정된 환경을 사용하며, 저장된 인스턴스가 같은 환경이면 그대로 사용해 중복 생성하지 않는다. 다른 환경이면 실행 중 인스턴스만 교체하고 편집 상태는 Play 종료 시 복원된다.
- 환경 프리팹 변경은 Unity의 프리팹 갱신을 따른다. 기존 Scene override가 있는 항목은 원본 변경보다 우선할 수 있다.

### 판정과 검증 범위

- 환경은 장식 전용이다. Collider·크기·위치가 현재 격자 이동 판정을 바꾸지 않는다. 이동을 막으려면 맵 에디터의 이동 불가 타일을 별도로 지정한다. 여러 칸 점유·문·상자·파괴 기능은 미구현이다.
- 코드: `GridMap.environmentPrefab`, `GridMapPlayer`의 환경 인스턴스/소스 참조, `Assets/IBIIIS/Editor/MapEnvironmentEditor.cs`. 편집 환경은 Scene에 저장하고, 타일 미리보기와 별도로 유지한다.
