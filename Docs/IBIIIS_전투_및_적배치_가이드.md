# 전투 진행과 맵 에디터 적 배치

갱신일: 2026-10-05. 최신 사용자 결정: 플레이어와 적들이 같은 입력에 동시에 이동을 시작한다. 맵은 사용자가 만든다. 이번 작업은 기존 맵 배치를 수정하거나 11×11 맵을 생성하지 않았다.

## 맵에서 적 배치

1. `IBIIIS > Map Editor`에서 사용할 GridMap을 선택한다. 11×11로 제작하려면 가로·세로에 11을 입력해 크기를 적용하고 바닥과 플레이어 시작 위치를 배치한다.
2. 하단 `적` 탭의 적 타일(Enemy001~003 등, 프로젝트의 EnemyDefinition 프리팹을 자동 수집)에서 하나를 클릭한다. 선택 시 `적 배치 N` 도구로 전환한다. 기본 프리팹은 `Assets/IBIIIS/Characters/Enemies/EnemyNNN/`에 있다.
3. `배치 방향` 버튼(또는 `R`/`Shift+R`)으로 방향을 정한 뒤 칸을 클릭 또는 드래그한다. 마우스 아래에 놓일 적과 방향이 미리 보이고, 놓을 수 없는 칸은 빨간 테두리로 표시된다. 삼각형의 색상은 적 종류, 꼭짓점은 진행 방향이다. 같은 칸에 다시 배치하면 기존 적의 종류·방향을 교체한다. 시작 위치나 이동 불가 칸에는 배치하지 못한다. 이미 놓은 적은 `선택 V` 도구로 고른 뒤 회전(`R`, 버튼)·삭제(`Delete`, 버튼)한다.
4. `적 지우기`는 바닥을 유지하고 적만 제거한다. 바닥 `지우기`는 해당 칸의 적도 제거한다. 맵 축소 시 범위 밖 적 배치도 제거하며 Undo/Redo로 복구 가능하다.
5. 오른쪽 클릭이나 선택 도구로 칸을 고르면 `선택한 칸`에 적 이름·방향·행동 목록이 나온다. 적에 마우스를 올리거나 선택하면 인식·공격 범위가 캔버스에 표시된다(`모든 적 범위`로 전체 표시). 상태 표시줄에는 적 수와 홀수 배치 안내가 나온다. 짝수 배치를 권장하지만 특정 수를 강제로 생성하지 않는다.
6. `저장` 후 연결된 씬을 연다. Scene에서도 배치한 적과 방향 표식이 보인다. 적은 자동 생성 영역이므로 Scene에서 생성된 적을 직접 옮기지 말고 맵 에디터에서 편집한다.

기본 프리팹은 생성 완료했다. `기본 적 프리팹 준비` 또는 `IBIIIS > Create Default Enemy Prefabs`는 누락된 기본 에셋만 생성하며 기존 프리팹·재질은 덮어쓰지 않는다. 기존 맵·씬은 변경하지 않는다.

## 프리팹 편집과 데이터

- EnemyDefinition에서 Enemy Id, Actions(행동 목록), Recognition, Attack, Recognized Attack, Editor Color를 편집한다. 범위 오프셋은 **X=진행 방향 기준 오른쪽, Y=앞**이다. `(0,0)`은 적이 서 있는 칸이다.
- **행동 목록(Actions)**: 플레이어 행동 한 번마다 위에서부터 순서대로 수행한다(2026-10-06). 단위는 `AimAtPlayer`(플레이어의 행동 직전 위치가 인식 범위 안이면 그쪽을 향함, 시간 소모 없음), `MoveForward`(바라보는 방향으로 1~2칸을 한 칸씩 이동, 막히면 180도 회전·그래도 막히면 머묾), `Turn`(제자리에서 왼쪽/오른쪽/뒤로 회전, 시간 소모 없음)이다. 전진 단위의 칸은 모든 적이 한 칸씩 동시에 진행하며 충돌 판정도 한 칸마다 이뤄진다. 기본 적 3종은 `[AimAtPlayer, MoveForward(1 또는 2)]`로 이전과 같다. `Turn`은 구조 확인용으로만 제공하며 아직 어떤 적에도 쓰지 않고, 이를 쓰는 패턴은 미정이다. 새 단위는 `EnemyActionType`(Runtime/EnemyBehavior.cs)에 추가하고 `GridSession.RunInstantActions`(시간 소모가 없으면) 또는 `PlanEnemyStep`(이동이면)에 처리를 더한다. 특정 적 이름을 검사하는 분기는 추가하지 않는다.
- **이전 데이터 호환**: Actions가 비어 있는 프리팹은 숨은 `moveCells`로 `[AimAtPlayer, MoveForward(moveCells)]`처럼 동작한다. Inspector에 안내가 나오며 `이전 설정을 행동 목록으로 변환` 버튼으로 목록을 채울 수 있다(목록이 이미 있으면 변경하지 않음). 기본 3종은 변환 완료 상태다. 한 번 목록을 쓰면 `moveCells`는 읽지 않는다.
- 기본 설정은 Word·HTML을 따른다. Enemy001/002의 인식은 전방 반원 맨해튼 거리 2, Enemy003은 좌우 1칸과 앞줄 3칸이다. Excel의 Enemy002 인식 도식과 다른 부분은 Word·HTML 기준을 채택했다.
- Enemy001은 한 칸 이동, 기본 공격은 도착 칸, 인식 후 앞 1칸 추가. Enemy002는 두 칸 이동, 기본 앞 1칸, 인식 후 앞 2칸까지. Enemy003은 한 칸 이동, 기본 도착·앞·앞오른쪽, 인식 후 오른쪽도 추가한다.
- 적 프리팹 루트에는 발밑 그림자(`GroundShadow`)와 진행 방향 화살표(`FacingArrow`, 4방향 스프라이트 도입 전 임시)가 중첩 프리팹으로 붙어 있다. 자세한 내용은 [에셋 제작 가이드](IBIIIS_에셋_제작_가이드.md)의 발밑 보정·그림자·화살표 항목을 따른다.
- `Visual`은 카메라를 바라볼 자식 Transform이다. 2026-10-06부터 Enemy001~003의 `Visual`은 `Characters/Enemies/Enemy00N/Enemy00N.png`(임시 러프 스케치, 594×506, PPU 600, 발밑 중앙 기준점)를 쓰는 SpriteRenderer이며, 크기는 `Visual`의 Scale로 조정한다(현재 1.5, 플레이어와 같은 배율). 실제 화면 확인은 사용자 확인 대기다. 자식 외형을 교체해도 논리적 이동·점유는 바뀌지 않는다. 프리팹 루트 변환은 게임에서 칸 위치·방향·Cell Size로 결정한다.
- GridMap은 프리팹 참조·좌표·방향을 저장한다. GridSession은 시작 시 이동 가능 영역과 적 규칙을 복사하고 개체별 위치·방향·생존 여부·경로를 별도로 관리한다. 프리팹 원본은 실행 중 변경하지 않는다.
- 자료의 좌표는 위쪽 행 0, 프로젝트는 아래쪽 Y=0이다. 배치를 옮길 때 `프로젝트 y = 맵 높이 - 1 - 자료 행`으로 변환한다. 11×11 자료의 플레이어 (5,10)은 프로젝트 (5,0)이다.

## 전투 진행과 조작

`Waiting → Moving(플레이어·적 동시 이동) → 양쪽 완료 후 공격·피격 판정 → Waiting / Won / Lost`

- 플레이어와 적은 동시에 이동한다. 먼저 도착한 쪽은 기다리며 양쪽 행동이 모두 끝나야 판정 후 다음 입력을 받는다. 진행 중 추가 입력은 예약하지 않는다.
- 아래 기본 키는 `Assets/IBIIIS/Settings/IBIIISInput.inputactions`의 `Battle` 맵 바인딩이다(2026-10-06). 키를 바꾸거나 게임패드를 추가하려면 이 에셋을 연다([개발 및 사용 가이드](IBIIIS_개발_및_사용_가이드.md)의 전투 입력). 동시에 눌렀을 때 우선순위: 재시작 → 범위 표시 → 되돌리기 → 대기 → 구르기(Q,E,Z,C) → 이동·대시(위,아래,왼쪽,오른쪽). 키를 누르고 있어도 반복 입력되지 않고 진행 중 입력은 예약되지 않는다.
- WASD/방향키: 한 칸 이동. Space: 제자리 대기. Shift+방향키 또는 WASD: 직선 2칸 대시. Q/E/Z/C: 좌상/우상/좌하/우하 구르기. R: 대기·승리·패배 상태에서 재시작.
- Backspace 또는 U: 마지막 플레이어 행동 한 번을 되돌린다(2026-10-06 추가, 제안 단계의 편의 기능이며 기획 확정은 아니다). 행동 시작 직전의 플레이어·적 위치·방향·생존, 인식 상태, 이동 경로, 공격 칸, 회피기 쿨다운, 승패 상태를 모두 복원하므로 패배·승리 직후에도 되돌릴 수 있다. 행동 진행 중에는 무시하며, 횟수 제한은 없다. R 재시작은 되돌리기 기록도 지운다.
- Tab: 적 범위 표시 전환. 입력 대기·승패 상태에서만 보이고 행동 진행 중에는 숨긴다. **노란 테두리 = 인식 범위, 빨간 칸 = 공격 범위**이며 이동 가능한 칸만 표시한다. 공격 범위는 현재 플레이어가 인식 범위 안이면 인식 후 공격 범위를, 아니면 기본 공격 범위를 그린다. 적의 **현재 위치·방향** 기준이므로 다음 행동에서 적이 이동·재조준한 뒤의 범위를 예측한 것이 아니다. 시작 시 표시 여부는 `IBIIIS > Player Settings`의 `Show Enemy Ranges`(기본 켬)에서 정하며, 표시 전용이라 판정에 쓰이지 않는다.
- 대시·구르기를 사용하면 다음 한 번의 일반 이동 또는 대기 행동 동안 회피기를 사용할 수 없다. 무적은 없다.
- 적이 점유한 목적지로 이동하지 못한다. 대시는 중간 칸도 검사하므로 몹이나 빈칸을 뛰어넘지 못한다. HTML에서 누락된 중간 몹 검사는 Word 규칙에 맞춰 추가했다. 구르기의 대각선 양옆 칸은 검사하지 않는다(HTML과 동일); 장애물의 대각선 통과 제한은 후속 규칙이다.
- **적은 플레이어가 이번 행동에서 어디로 이동할지 모른다**(2026-10-06 변경). 인식·재조준은 플레이어의 행동 시작 직전 위치만으로 판단하며, 이 위치는 행동 중 플레이어가 먼저 도착하더라도 그 행동이 끝날 때까지 바뀌지 않는다. 적은 거리가 더 먼 축을 향하고, 동률이면 그 방향을 향하고 있지 않을 때만 직교 방향으로 튼다. 이전에는 선택한 목적지를 기준으로 삼았으며, 그 방식의 전수 탐색·배치 자료는 이 규칙에서 재검증되지 않았다.
- 한 칸씩 모든 적의 도착 위치를 동시에 확정한 뒤 겹친 적을 모두 제거한다. 서로 자리를 맞바꾸는 것은 충돌이 아니다. 두 칸 적은 이 과정을 두 번 거치며, 두 번째 이동에서는 한 칸 적의 정지한 위치와도 충돌한다.
- 경계나 이동 불가 칸 앞에서는 180도 돌아 같은 행동 안에 이동한다. 돌아선 칸도 막혔으면 그 자리에 머문다. 내부 장애물은 기존 배치 검증 범위 밖이다.
- 이동 후 인식은 공격 범위만 바꾸고 재조준하지 않는다. 살아남은 적의 공격 범위 또는 이번 행동의 이동 경로에 플레이어가 있으면 즉시 패배한다. 충돌로 죽은 적의 경로는 피격에 포함하지 않는다(HTML 기준).
- 적끼리는 공격 범위로 죽지 않고 직접적인 칸 충돌로만 죽는다. 배치한 적이 전멸하면 승리한다. 적을 하나도 배치하지 않은 맵은 이동 테스트용으로 유지하며 즉시 승리하지 않는다.

## 이동 시간과 표시

- `IBIIIS > Player Settings`의 Move Duration은 플레이어 한 칸 이동 시간이다. 대시 연출은 두 배, 구르기·대기는 같은 시간을 사용한다. 기본 0.25초는 임시 연출 값이다.
- Enemy Step Duration은 적 한 칸 이동 연출 시간이다(기본 0.25초). 2칸 적은 두 번 이동한다. 각 행동 시작 시 두 시간을 고정한다. 연출 시간이 판정 결과를 바꾸지 않게 처리한다.
- 게임 시간은 플레이어와 적 행동이 모두 끝날 때까지 진행하고 입력 대기·승패 상태에서 정지한다. timeScale은 게임 오브젝트 비활성화·제거 시 원래 값으로 복구한다.
- 이동 가능 인접 칸, 대시 목적지(파랑), 구르기 목적지(보라)를 표시한다. 플레이어가 이동하는 동안 목적지만 표시한다. 플레이어가 먼저 도착한 뒤 적이 계속 이동하는 동안에는 플레이어 이동 표시를 숨긴다. 적 점유·회피기 쿨다운을 실제 행동 가능 판정과 동일하게 반영한다.
- 패배(피격) 애니메이션과 패배 연출은 아직 없다. 승패는 현재 디버그 HUD로 표시한다. 적끼리 충돌 연출은 아래 항목을 따른다.

## 충돌 연출 — 2026-10-06

- **순서**: 두 적 이상이 같은 칸에 도착한 순간 ① 맞닿음(적이 납작해졌다 돌아오며 붉게 번쩍임, 0.08초)과 동시에 충돌 칸에 별 모양 충격 이펙트·효과음·화면 흔들림(0.18초)이 시작된다. ② 이어서 0.08초 멈춤 — 맞닿음과 합친 0.16초 동안 다른 적과 플레이어의 움직임도 멈춘다. ③ 적들이 들어온 방향의 반대로 튕겨 회전하며 날아가 사라진다(0.35초). 날아가는 동안 발밑 그림자·화살표는 숨긴다. 한 충돌 연출은 약 0.5초다.
- **판정과 분리**: 충돌·사망·승패 판정은 이전과 같고 연출은 그 결과를 보여 주기만 한다. `GridSession.Collisions`(칸·이동 단계·참여 적)를 읽어 `CollisionFeedback`이 재생한다. 연출을 끄거나 시간을 바꿔도 결과는 같다(자동 테스트로 확인).
- **입력**: 연출이 끝날 때까지 다음 입력을 받지 않으며 게임 시간도 흐른다. 승리·패배가 확정된 행동이라도 연출이 끝난 뒤 입력을 받는다. 되돌리기·재시작은 진행 중인 연출을 즉시 정리하고 적을 원래 모습으로 되돌린다.
- **설정**: `Assets/IBIIIS/Settings/CollisionFeedback.asset`(`IBIIIS > Player Settings`의 `Collision Feedback` 슬롯에 연결)에서 켜고 끄기, 맞닿음·멈춤 시간, 납작해지는 정도, 충격 이펙트 프리팹·시간·크기, 흔들림 세기(칸)·시간, 효과음·음량, 날아가는 시간을 바꾼다. 날아가는 거리(칸)·최고 높이(칸)·회전 수는 `최소 ~ 최대` 범위로 정하며, 적마다 그 사이에서 무작위로 골라 매번 조금씩 다르게 날아간다(기본 거리 1~1.8, 높이 0.5~0.9, 회전 1~2바퀴; 도는 방향은 충돌한 적마다 번갈아 바뀜). 최소가 최대보다 크면 Inspector에 주황색으로 표시되고 실행 시 두 값을 바꿔 쓴다. 슬롯이 비어 있으면 그 연출만 건너뛴다. 설정 에셋 자체가 없으면 기본 수치로 이펙트·효과음 없이 재생한다. 강도는 임시값이며 사용자 확인 후 조정한다.
- **임시 에셋**: 충격 이펙트 `Assets/IBIIIS/Effects/CollisionBurst.prefab`(만화풍 별 `CollisionBurst.png`), 효과음 `Assets/IBIIIS/Audio/CollisionImpact.wav`(코드로 합성한 0.3초 "쿵·퍽"). 메뉴 `IBIIIS > Create Default Collision Feedback`가 없을 때만 만들고 설정·연결이 비어 있을 때만 채운다. 정식 그림·소리는 파일을 교체하거나 설정 슬롯을 바꾼다.
- **검증**: 컴파일 완료, EditMode 71/71 통과(신규 6: 충돌 기록의 칸·단계·참여 적과 되돌리기 시 초기화, 충돌에서 멈추는 시간 진행이 결과를 바꾸지 않음, 연출 중 입력 차단·연출 후 숨김·카메라/외형 복원, 멈춤 동안 다른 적 정지 후 재개, 연출 중 되돌리기 복원, 연출 끔/설정 없음 처리). Play 모드의 `ProtoTypeMap`에서 맵 검증으로 찾은 승리 경로 11행동을 실행해 충돌 연출 2회와 효과음 재생기 생성, 승리, 콘솔 오류 없음을 확인했다(에디터가 Play 프레임을 진행하지 않아 시간은 코드로 진행). 실제 화면의 느낌·소리 크기·흔들림 강도는 사용자 확인 대기다.
