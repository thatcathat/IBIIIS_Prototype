# 전투 진행과 맵 에디터 적 배치

갱신일: 2026-10-06. 현재 프로토타입에 채택한 전투 규칙, 적 프리팹 설정과 맵 배치 절차를 담당한다. 공통 기획과 미정 사항은 [게임 시스템 기획서](IBIIIS_게임시스템_기획서.md)에 있다. 맵은 사용자가 만들며, 에이전트 작업은 기존 맵 배치를 자동으로 수정하지 않는다.

## 맵에서 적 배치

1. `IBIIIS > Map Editor`에서 사용할 GridMap을 선택한다. 11×11로 제작하려면 가로·세로에 11을 입력해 크기를 적용하고 바닥과 플레이어 시작 위치를 배치한다.
2. 하단 `적` 탭의 적 타일(Enemy001~003 등, 프로젝트의 EnemyDefinition 프리팹을 자동 수집)에서 하나를 클릭한다. 선택 시 `적 배치 N` 도구로 전환한다. 기본 프리팹은 `Assets/IBIIIS/Prefabs/Characters/Enemies/`에 있다.
3. `배치 방향` 버튼(또는 `R`/`Shift+R`)으로 방향을 정한 뒤 칸을 클릭 또는 드래그한다. 마우스 아래에 놓일 적과 방향이 미리 보이고, 놓을 수 없는 칸은 빨간 테두리로 표시된다. 삼각형의 색상은 적 종류, 꼭짓점은 진행 방향이다. 같은 칸에 다시 배치하면 기존 적의 종류·방향을 교체한다. 시작 위치나 이동 불가 칸에는 배치하지 못한다. 이미 놓은 적은 `선택 V` 도구로 고른 뒤 회전(`R`, 버튼)·삭제(`Delete`, 버튼)한다.
4. `적 지우기`는 바닥을 유지하고 적만 제거한다. 바닥 `지우기`는 해당 칸의 적도 제거한다. 맵 축소 시 범위 밖 적 배치도 제거하며 Undo/Redo로 복구 가능하다.
5. 오른쪽 클릭이나 선택 도구로 칸을 고르면 `선택한 칸`에 적 이름·방향·행동 목록이 나온다. 적에 마우스를 올리거나 선택하면 인식·공격 범위가 캔버스에 표시된다(`모든 적 범위`로 전체 표시). 상태 표시줄에는 적 수와 홀수 배치 안내가 나온다. 짝수 배치를 권장하지만 특정 수를 강제로 생성하지 않는다.
6. `저장` 후 연결된 씬을 연다. Scene에서도 배치한 적과 방향 표식이 보인다. 적은 자동 생성 영역이므로 Scene에서 생성된 적을 직접 옮기지 말고 맵 에디터에서 편집한다.

`기본 적 프리팹 준비` 또는 `IBIIIS > Create Default Enemy Prefabs`는 없는 기본 적(Enemy001~003) 프리팹만 현재 규격으로 만든다: 루트 `EnemyDefinition`, 자식 `Visual`(SpriteRenderer, 위치 (0, 0.02, 0), Scale 1.5), 발밑 그림자·진행 방향 화살표. 그림은 폴더에 `<이름>.png`가 있으면 그것을, 없으면 코드로 그린 임시 그림 `<이름>_Placeholder.png`(256×256, PPU 256, 기준점 아래 중앙)를 쓴다. 이미 있는 적 프리팹·맵·씬은 바꾸지 않으며, 직접 지운 `FacingArrow`도 되살리지 않는다. 재질 에셋은 만들지 않는다.

## 프리팹 편집과 데이터

- EnemyDefinition에서 Enemy Id, Actions(행동 목록), Recognition, Attack, Recognized Attack, Editor Color를 편집한다. 설정이 잘못되면(Enemy Id 빈칸, 전진 칸 수 범위 밖, 범위 없음) Inspector에 이유가 오류로 표시되고, 맵 검증·적 팔레트에도 프리팹 누락·EnemyDefinition 없음·설정 오류를 구분해 이유를 보여 준다. 범위 오프셋은 **X=진행 방향 기준 오른쪽, Y=앞**이다. `(0,0)`은 적이 서 있는 칸이다.
- **행동 목록(Actions)**: 플레이어 행동 한 번마다 위에서부터 순서대로 수행한다. 단위는 `AimAtPlayer`(플레이어의 행동 직전 위치가 인식 범위 안이면 그쪽을 향함, 시간 소모 없음), `MoveForward`(바라보는 방향으로 1~2칸을 한 칸씩 이동, 막히면 180도 회전·그래도 막히면 머묾), `Turn`(제자리에서 왼쪽/오른쪽/뒤로 회전, 시간 소모 없음)이다. 전진 단위의 칸은 모든 적이 한 칸씩 동시에 진행하며 충돌 판정도 한 칸마다 이뤄진다. 기본 적 3종은 `[AimAtPlayer, MoveForward(1 또는 2)]`이다. `Turn`은 구조 확인용으로만 제공하며 아직 어떤 적에도 쓰지 않고, 이를 쓰는 패턴은 미정이다. 모든 적이 조준·회전만 하는 행동에서는 적 이동 단계를 쓰지 않으므로 행동 시간이 플레이어 이동 시간과 같다. 새 단위는 `EnemyActionType`(Scripts/Runtime/Battle/EnemyBehavior.cs)의 **맨 끝에 새 정수 값으로** 추가하고(프리팹에 정수로 저장되므로 기존 값을 바꾸거나 중간에 끼우면 기존 적의 행동이 조용히 바뀐다) `GridSession.RunInstantActions`(시간 소모가 없으면) 또는 `PlanEnemyStep`(이동이면)에 처리를 더한다. 특정 적 이름을 검사하는 분기는 추가하지 않는다.
- **이전 데이터 호환**: Actions가 비어 있는 프리팹은 숨은 `moveCells`로 `[AimAtPlayer, MoveForward(moveCells)]`처럼 동작한다. Inspector에 안내가 나오며 `이전 설정을 행동 목록으로 변환` 버튼으로 목록을 채울 수 있다(목록이 이미 있으면 변경하지 않음). 기본 3종은 변환 완료 상태다. 한 번 목록을 쓰면 `moveCells`는 읽지 않는다.
- 기본 설정은 사용자 제공 Word·HTML 자료를 따른다. Enemy001/002의 인식은 전방 반원 맨해튼 거리 2, Enemy003은 좌우 1칸과 앞줄 3칸이다. 제공된 Excel의 Enemy002 인식 도식과 다른 부분은 Word·HTML 기준을 채택했다.
- Enemy001은 한 칸 이동, 기본 공격은 도착 칸, 인식 후 앞 1칸 추가. Enemy002는 두 칸 이동, 기본 앞 1칸, 인식 후 앞 2칸까지. Enemy003은 한 칸 이동, 기본 도착·앞·앞오른쪽, 인식 후 오른쪽도 추가한다.
- 적 프리팹 루트에는 발밑 그림자(`GroundShadow`)와 진행 방향 화살표(`FacingArrow`, 4방향 스프라이트 도입 전 임시)가 중첩 프리팹으로 붙어 있다. 자세한 내용은 [에셋 제작 가이드](IBIIIS_에셋_제작_가이드.md)의 발밑 보정·그림자·화살표 항목을 따른다.
- `Visual`은 카메라를 바라볼 자식 Transform이다. Enemy001~003의 `Visual`은 `Art/Sprites/Enemies/Enemy00N.png`(임시 러프 스케치, 594×506, PPU 600, 발밑 중앙 기준점)를 쓰는 SpriteRenderer이며, 크기는 `Visual`의 Scale로 조정한다(현재 1.5, 플레이어와 같은 배율). 자식 외형을 교체해도 논리적 이동·점유는 바뀌지 않는다. 프리팹 루트 변환은 게임에서 칸 위치·방향·Cell Size로 결정한다.
- GridMap은 프리팹 참조·좌표·방향을 저장한다. GridSession은 시작 시 이동 가능 영역과 적 규칙을 복사하고 개체별 위치·방향·생존 여부·경로를 별도로 관리한다. 프리팹 원본은 실행 중 변경하지 않는다.
- 제공 자료의 좌표는 위쪽 행 0, 프로젝트는 아래쪽 Y=0이다. 배치를 옮길 때 `프로젝트 y = 맵 높이 - 1 - 자료 행`으로 변환한다. 11×11 자료의 플레이어 (5,10)은 프로젝트 (5,0)이다.

## 전투 진행과 조작

`Waiting → Moving(플레이어·적 동시 이동) → 양쪽 완료 후 공격·피격 판정 → Waiting / Won / Lost`

- 플레이어와 적은 동시에 이동한다. 먼저 도착한 쪽은 기다리며 양쪽 행동이 모두 끝나야 판정 후 다음 입력을 받는다. 진행 중 추가 입력은 예약하지 않는다.
- 아래 기본 키는 `Assets/IBIIIS/ScriptableObjects/Settings/IBIIISInput.inputactions`의 `Battle` 맵 바인딩이다. 키를 바꾸거나 게임패드를 추가하려면 이 에셋을 연다([개발 및 사용 가이드](IBIIIS_개발_및_사용_가이드.md)의 전투 입력). 동시에 눌렀을 때 우선순위: 재시작 → 범위 표시 → 되돌리기 → 대기 → 구르기(Q,E,Z,C) → 이동·대시(위,아래,왼쪽,오른쪽). 키를 누르고 있어도 반복 입력되지 않는다.
- WASD/방향키: 한 칸 이동. Space: 제자리 대기. Shift+방향키 또는 WASD: 직선 2칸 대시. Q/E/Z/C: 좌상/우상/좌하/우하 구르기. R: 대기·승리·패배 상태에서 재시작.
- Backspace 또는 U: 마지막 플레이어 행동 한 번을 되돌린다(제안 단계의 편의 기능이며 기획 확정은 아니다). 행동 시작 직전의 플레이어·적 위치·방향·생존, 인식 상태, 이동 경로, 공격 칸, 회피기 쿨다운, 플레이어가 바라보던 방향(대기를 되돌려도 대기 전 방향), 승패 상태를 모두 복원하므로 패배·승리 직후에도 되돌릴 수 있다. 행동 진행 중에는 무시하며, 횟수 제한은 없다. R 재시작은 되돌리기 기록도 지운다.
- Tab: 적 범위 표시 전환. 입력 대기·승패 상태에서만 보이고 행동 진행 중에는 숨긴다. **노란 테두리 = 인식 범위, 빨간 칸 = 공격 범위**이며 이동 가능한 칸만 표시한다. 공격 범위는 현재 플레이어가 인식 범위 안이면 인식 후 공격 범위를, 아니면 기본 공격 범위를 그린다. 적의 **현재 위치·방향** 기준이므로 다음 행동에서 적이 이동·재조준한 뒤의 범위를 예측한 것이 아니다. 시작 시 표시 여부는 `IBIIIS > Player Settings`의 `Show Enemy Ranges`(기본 켬)에서 정하며, 표시 전용이라 판정에 쓰이지 않는다.
- 대시·구르기를 사용하면 다음 한 번의 일반 이동 또는 대기 행동 동안 회피기를 사용할 수 없다. 무적은 없다.
- 적이 점유한 목적지로 이동하지 못한다. 대시는 중간 칸도 검사하므로 몹이나 빈칸을 뛰어넘지 못한다(HTML에는 중간 몹 검사가 없으나 Word 규칙을 채택). 구르기의 대각선 양옆 칸은 검사하지 않는다(HTML과 동일). 장애물의 대각선 통과 제한은 미정이다.
- **적은 플레이어가 이번 행동에서 어디로 이동할지 모른다**. 인식·재조준은 플레이어의 행동 시작 직전 위치만으로 판단하며, 이 위치는 행동 중 플레이어가 먼저 도착하더라도 그 행동이 끝날 때까지 바뀌지 않는다. 적은 거리가 더 먼 축을 향하고, 동률이면 그 방향을 향하고 있지 않을 때만 직교 방향으로 튼다.
- 한 칸씩 모든 적의 도착 위치를 동시에 확정한 뒤 겹친 적을 모두 제거한다. 서로 자리를 맞바꾸는 것은 충돌이 아니다. 두 칸 적은 이 과정을 두 번 거치며, 두 번째 이동에서는 한 칸 적의 정지한 위치와도 충돌한다.
- 경계나 이동 불가 칸 앞에서는 180도 돌아 같은 행동 안에 이동한다. 돌아선 칸도 막혔으면 그 자리에 머문다.
- 이동 후 인식은 공격 범위만 바꾸고 재조준하지 않는다. 살아남은 적의 공격 범위 또는 이번 행동의 이동 경로에 플레이어가 있으면 즉시 패배한다. 충돌로 죽은 적의 경로는 피격에 포함하지 않는다(HTML 기준).
- 적끼리는 공격 범위로 죽지 않고 직접적인 칸 충돌로만 죽는다. 배치한 적이 전멸하면 승리한다. 적을 하나도 배치하지 않은 맵은 이동 테스트용으로 유지하며 즉시 승리하지 않는다.

## 이동 시간과 표시

- `IBIIIS > Player Settings`의 Move Duration은 플레이어 한 칸 이동 시간이다. 대시 연출은 두 배, 구르기·대기는 같은 시간을 사용한다. 기본 0.25초는 임시 연출 값이다.
- Enemy Step Duration은 적 한 칸 이동 연출 시간이다(기본 0.25초). 2칸 적은 두 번 이동한다. 각 행동 시작 시 두 시간을 고정한다. 연출 시간이 판정 결과를 바꾸지 않게 처리한다.
- 게임 시간은 플레이어와 적 행동이 모두 끝날 때까지 진행하고 입력 대기·승패 상태에서 정지한다. timeScale은 게임 오브젝트 비활성화·제거 시 원래 값으로 복구한다.
- 이동 가능 인접 칸, 대시 목적지(파랑), 구르기 목적지(보라)를 표시한다. 플레이어가 이동하는 동안 목적지만 표시한다. 플레이어가 먼저 도착한 뒤 적이 계속 이동하는 동안에는 플레이어 이동 표시를 숨긴다. 적 점유·회피기 쿨다운을 실제 행동 가능 판정과 동일하게 반영한다.
- 상태는 전투 HUD(스테이지 이름·남은 적·행동 횟수·회피기 아이콘과 쿨타임 남은 턴·조작 안내·되돌리기·다시 시작·범위 표시 버튼)로 표시한다. 화면 구성과 교체 방법은 [개발 및 사용 가이드](IBIIIS_개발_및_사용_가이드.md)의 게임 화면 UI 항목을 따른다. 적끼리 충돌과 플레이어 패배의 연출은 아래 충돌 연출 항목을 따른다.

## 충돌 연출

- **순서**: 두 적 이상이 같은 칸에 도착한 순간 ① 맞닿음(적이 납작해졌다 돌아오며 붉게 번쩍임, 0.08초)과 동시에 충돌 칸에 별 모양 충격 이펙트·효과음·화면 흔들림(0.18초)이 시작된다. ② 이어서 0.08초 멈춤 — 맞닿음과 합친 0.16초 동안 다른 적과 플레이어의 움직임도 멈춘다. ③ 적들이 들어온 방향의 반대로 튕겨 회전하며 날아가 사라진다(0.35초). 날아가는 동안 발밑 그림자·화살표는 숨긴다.
- **플레이어 패배**: 플레이어는 날아가지 않는다(사용자 결정, 2026-10-13). 그 자리에서 패배 그림으로 바뀌어 좌우로 떨며, 되돌리기·재시작 전까지 유지된다. 아래 상황별 플레이어 그림 항목을 따른다. `GridSession.Attackers`(플레이어를 공격 범위나 이동 경로로 맞힌 적)는 판정 기록으로 남아 있다.
- **판정과 분리**: 연출은 판정 결과를 보여 주기만 한다. `GridSession.Collisions`(칸·이동 단계·참여 적)를 읽어 `CollisionFeedback`이 재생한다. 연출을 끄거나 시간을 바꿔도 결과는 같다.
- **입력**: 연출이 끝날 때까지 다음 입력을 받지 않으며 게임 시간도 흐른다. 승리·패배가 확정된 행동이라도 연출이 끝난 뒤 입력을 받는다. 되돌리기·재시작은 진행 중인 연출을 즉시 정리하고 적을 원래 모습으로 되돌린다.
- **설정**: `Assets/IBIIIS/ScriptableObjects/Settings/CollisionFeedback.asset`(`IBIIIS > Player Settings`의 `Collision Feedback` 슬롯에 연결)에서 켜고 끄기, 맞닿음·멈춤 시간, 납작해지는 정도, 충격 이펙트 프리팹·시간·크기, 흔들림 세기(칸)·시간, 효과음·음량, 날아가는 시간을 바꾼다. 날아가는 거리(칸)·최고 높이(칸)·회전 수는 `최소 ~ 최대` 범위로 정하며, 적마다 그 사이에서 무작위로 골라 매번 조금씩 다르게 날아간다(도는 방향은 충돌한 적마다 번갈아 바뀜). 코드 기본값은 거리 1~1.8, 높이 0.5~0.9, 회전 1~2바퀴이고, 현재 에셋 값은 거리 10~15, 높이 3~7, 회전 1~2바퀴다. 거리 10~15와 높이 3~7은 사용자가 의도한 값이다(사용자 확인, 2026-10-06). 최소가 최대보다 크면 Inspector에 주황색으로 표시되고 실행 시 두 값을 바꿔 쓴다. 슬롯이 비어 있으면 그 연출만 건너뛴다. 설정 에셋 자체가 없으면 기본 수치로 이펙트·효과음 없이 재생한다. 강도는 임시값이며 사용자 확인 후 조정한다.
- **임시 에셋**: 충격 이펙트 `Assets/IBIIIS/VFX/CollisionBurst.prefab`(만화풍 별 `CollisionBurst.png`), 효과음 `Assets/IBIIIS/Audio/SFX/CollisionImpact.wav`(코드로 합성한 0.3초 "쿵·퍽"). 메뉴 `IBIIIS > Create Default Collision Feedback`가 파일을 없을 때만 만들고, 설정 에셋이 이미 있어도 비어 있는 `Impact Prefab`·`Impact Sound` 슬롯과 공용 플레이어 설정의 연결만 채운다. 연결된 슬롯은 바꾸지 않는다. 정식 그림·소리는 파일을 교체하거나 설정 슬롯을 바꾼다.

## 상황별 플레이어 그림 (2026-10-13)

사용자 결정으로 전투 상황에 따라 플레이어 그림을 바꾼다. 표시 전용이며 판정·위치·시간은 바뀌지 않는다.

| 상황 | 판정 기준 | 그림(기본 연결) | 표시 |
|---|---|---|---|
| 위험 | 입력 대기 중 살아 있는 적 하나라도 플레이어 칸을 인식 범위로 보고 있음 | `c_danger` | 대기 그림 대신. 이동 중에는 일반 이동 그림. `GridMapPlayer.DangerIdleEnabled`가 false면(튜토리얼 대본 중) 자동으로 보이지 않음 |
| 회피 | 대시·구르기를 했고, 그 행동 대신 제자리 대기를 했다면 패배였는데 패배하지 않음 | `c_danger_cleared` → `c_danger_cleared_2` | 판정이 끝나면 장마다 0.4초씩 순서대로, 으쓱 움직임 |
| 벗어남 | 한 칸 이동(대시·구르기 아님)을 했고, 행동 전에는 인식 범위 안·행동 뒤에는 어느 적의 인식 범위에도 없음 | `c_danger_gone` | 0.4초, 한숨 움직임 |
| 패배 | 패배 확정 | `c_defeated` | 좌우 떨림, 되돌리기·재시작 전까지 유지 |

- 우선순위: 대본의 자세 그림 > 패배·회피·벗어남 그림 > 위험 그림 > 일반 그림. 패배와 다른 반응이 겹치면 패배만 보인다. 다음 행동을 시작하면 남은 반응 그림은 지운다. 되돌리면 반응 없이 그 상태의 그림으로 바로 맞춘다.
- 「회피」의 '공격을 피함'은 '제자리에 있었으면 맞았을 공격'으로 정했다(에이전트 해석, 사용자 확인 필요 — [플레이 확인 목록](IBIIIS_플레이_확인_목록.md) B-06). 판정은 행동 직전 상태의 복사본으로 대기를 미리 계산한다(`GridSession.Predict`).
- 설정: 플레이어 외형 프리팹 `Prefabs/Characters/Player/PlayerVisual.prefab`의 `PlayerVisual > 상황별 그림` — `Danger`, `Evaded`(순서대로, 장 수 자유), `Escaped`, `Defeated`, `Reaction Frame Seconds`(임시 0.4초). 슬롯이 비면 그 상황은 일반 그림을 쓴다. 움직임 종류(으쓱·한숨·떨림)는 코드에 둔 임시 선택이다.
- 생성: `IBIIIS > Create Default Player Visual`이 프리팹의 빈 상황별 슬롯만 `Art/Sprites/Player`의 같은 이름 그림으로 채운다. 연결한 슬롯은 바꾸지 않는다.
- 코드: `GridMapPlayer`(행동 시작 때 기록, 판정 뒤 `ChooseReaction`, 매 프레임 `TickReaction`), `PlayerVisual`(`ReactionSprite`·`InDanger`·`OverrideSprite`로 그림 선택).
- 개발 검증: EditMode 자동 테스트로 패배 시 그 자리에서 패배 그림(날아가지 않음·충격 이펙트 없음)이 되돌리기 전까지 유지됨, 대시 회피 시 두 그림이 순서대로 나온 뒤 원래 그림, 인식 범위 안 대기의 위험 그림과 이동으로 벗어난 뒤의 벗어남 그림, 되돌리면 다시 위험 그림을 확인했다.
- 사용자 확인 대기: [플레이 확인 목록](IBIIIS_플레이_확인_목록.md) B-06. 새 그림들도 Foot Offset 0.15를 같이 받는다.

- **이동(1칸)**: 출발 구간(진행도 18%)에 웅크렸다가 포물선으로 통통 뛰고(최고 0.25칸) 공중에서 위아래로 늘어난다. 착지하면 납작해졌다 돌아오고(0.14초, 입력은 막지 않음) 발밑 양옆으로 먼지가 퍼지며 발소리가 난다. 만화풍으로 세게 잡은 임시 수치다.

## 적 인식 말풍선 — 2026-10-11 (이전 !·? 그림 대체)

- **인식 기준**: 입력 대기·승패 상태에서 플레이어의 현재 칸이 적의 인식 범위 안이면 "인식 중"이다. 적의 현재 위치·방향 기준이며 "지금 공격 범위가 인식 후 범위다"(Tab 범위 표시의 빨간 칸)와 같은 기준이다(`GridSession.IsRecognizing`). 행동 목록이 `AimAtPlayer`로 시작하는 적(기본 3종)이면 "다음 행동에서 플레이어 쪽으로 조준한다"와도 일치한다. 조준 앞에 회전·전진이 있는 적은 그 뒤 위치에서 다시 판정하므로 다를 수 있다(말풍선이 실제 조준을 예고해야 하는지는 미정).
- **새로 인식할 때**: 대사 쌍(플레이어 말 → 적 대답) 하나를 무작위로 골라 플레이어 머리 위에 플레이어 말을 띄우고, `Reply Delay`(임시 0.4초) 뒤 새로 인식한 적 **모두**가 대답한다. 대사 쌍은 첫 번째로 새로 인식한 적의 대사 목록에서 고르며, 같은 목록을 쓰는 적은 같은 대답을, 다른 목록을 쓰는 적은 자기 목록의 대답을 한다. 말풍선은 `Spotted Time`(임시 1.5초) 동안 보이고 마지막 25%에 흐려진다. 효과음은 한 번이다. 인식이 이어지는 동안 다시 말하지 않는다. 전투 시작 시 이미 범위 안이면 바로 대화한다.
- **인식에서 벗어날 때**: 그 적이 혼잣말 목록(개별 대사)에서 하나를 골라 `Lost Line Time`(임시 1.2초) 동안 말한다. 목록이 비면 아무 말도 하지 않는다. 플레이어는 말하지 않는다.
- **반복 방지**: 대사 에셋의 `No Immediate Repeat`를 체크하면 바로 직전에 나온 대사(쌍)는 다음에 고르지 않는다(목록이 2개 이상일 때). 직전 대사 기억은 실행 중인 전투가 가지며 에셋은 바뀌지 않는다.
- 행동 진행 중과 충돌·패배 연출 중에는 말풍선을 모두 지우고, 판정이 끝난 뒤 행동 전 상태와 비교해 반응한다. 그래서 빨리 다음 행동을 하면 남은 말풍선은 다시 나오지 않는다. 충돌로 사라진 적의 말풍선도 지운다. 되돌리기를 하면 말풍선·효과음 없이 그 상태에 바로 맞춘다.
- **위치·모양**: 말하는 이의 발밑에서 화면 위쪽(카메라 위 방향)으로 적은 `Height`, 플레이어는 `Player Height`(둘 다 임시 1.45칸)만큼 올린 곳에 말풍선 꼬리 끝이 온다. 말풍선은 전투 HUD 화면(UI Toolkit)의 `bubbles` 층에 그리며, 모양은 `Assets/IBIIIS/UI/SpeechBubble.uxml`(요소 이름 `bubble`·`text` 유지)과 `GameUi.uss`의 `speech-*` 스타일(흰 둥근 말풍선·아래 꼬리·굵은 글자, 플레이어 말풍선은 연노랑 `.player`)에서 바꾼다. **등장**: 최종 위치보다 `Rise Distance`(임시 20px, 1920×1080 기준) 아래에서 투명하게 나타나 `Appear Time`(임시 0.35초) 동안 감속하며 떠오르고, 그동안 꼬리를 축으로 좌우로 흔들린다. 처음에 `Wobble Angle`(임시 10°)만큼 가장 크게 기운 뒤 `Wobbles`(임시 2.5)번 흔들리며 폭이 빠르게 줄어(약 10°→6°→3°→2°) 도착하면 멈춘다. 첫 큰 흔들림이 보이도록 처음 10% 시간에 나타난다. 크기는 `Start Scale`(임시 0.8배)에서 1배로 커진다. 플레이어 말·적 대답·적 혼잣말 모두 같다(2026-10-11 사용자 결정). Game UI 설정이 없으면 말풍선을 그리지 않는다(효과음은 남).
- **대사 편집**: 공용 대사는 `Assets/IBIIIS/ScriptableObjects/Settings/BattleDialogue.asset`(`Enemy Alert` 설정의 `Dialogue` 슬롯). `Spotted`에 플레이어 말·적 대답 쌍을, `Lost`에 적 혼잣말을 추가한다. 빈칸이면 그 말은 생략한다. 특정 적만 다른 대사를 쓰려면 `Assets > Create > IBIIIS > Battle Dialogue`로 새 에셋을 만들어 그 적 프리팹 `EnemyDefinition`의 `Dialogue` 슬롯에 연결한다(비우면 공용 대사).
- **설정**: `Assets/IBIIIS/ScriptableObjects/Settings/EnemyAlert.asset`(`IBIIIS > Player Settings`의 `Enemy Alert` 슬롯) — 켜기/끄기, `Dialogue`(공용 대사), `Height`·`Player Height`, `Reply Delay`, `Spotted Time`, `Lost Line Time`, 등장(`Appear Time`·`Rise Distance`·`Wobble Angle`·`Wobbles`·`Start Scale`), 효과음·음량. 메뉴 `IBIIIS > Create Default Enemy Alert`가 없는 에셋만 만들고(임시 대사 3쌍·혼잣말 3개) 빈 슬롯만 채운다. 말풍선 화면 구성은 `IBIIIS > Create Default Game UI`가 Game UI 설정의 `Speech Bubble` 슬롯에 연결한다.
- **판정과 분리**: 표시 전용이며 판정에 쓰지 않는다. 코드: `Scripts/Runtime/Feedback/EnemyAlert.cs`(말풍선 상태·그리기), `Scripts/Runtime/Feedback/BattleDialogue.cs`, `Scripts/Runtime/Feedback/EnemyAlertSettings.cs`, `GridMapPlayer.UpdateAlert`, `Scripts/Editor/Setup/EnemyAlertSetup.cs`.
- **검증**: EditMode 149/149 통과(신규·변경 8: 인식 순간 플레이어 말 → 지연 뒤 적 대답·시간 뒤 사라짐·계속 인식 중이면 다시 말하지 않음, 동시에 인식한 적 모두 대답·플레이어 말은 한 번, 벗어나면 적 혼잣말·다음 행동 뒤 다시 나오지 않음, 적별 대사 우선, 반복 방지 체크 시 연달아 같은 쌍 없음·대답은 고른 쌍과 짝, 등장 자세(아래에서 시작해 계속 떠오름·처음에 가장 크게 기울고 흔들릴수록 폭이 줄어듦·도착 시 위치 0·기울기 0·크기 1), 되돌리기는 말풍선·효과음 없이 맞춤, 범위 밖·끔·대사 없음). Play 모드 개발 검증(`ProtoTypeMap`, 코드로 행동 진행): 인식 순간 플레이어 머리 위 "앗…!"과 적 머리 위 "찾았다!" 말풍선이 한글 글꼴로 각자 머리 위에 그려지는 것을 스크린샷으로 확인했다.

## 대본용 전투 확장 — 2026-10-12

튜토리얼 대본(개발 가이드의 튜토리얼 대본 진행)이 쓰는 판정 확장이다. 일반 맵의 규칙은 바뀌지 않는다.

- **적 합류**: 입력 대기 중에만 적을 추가할 수 있다. 이동 가능한 빈 칸(플레이어·살아 있는 적 없음)과 상하좌우 방향이 필요하다. 합류한 적은 다음 행동부터 움직이고 인식·공격·충돌 판정에 참여한다(합류한 턴의 공격 판정에는 참여하지 않는다는 기획서 규칙과 같다). 합류 전 행동을 되돌리면 합류한 적이 빠진다.
- **막힌 칸**: 실행 중 칸을 막을 수 있다(칸만 막는 오브젝트). 맵의 이동 불가 칸과 같아서 플레이어가 들어갈 수 없고 적은 그 앞에서 돌아선다. 플레이어·살아 있는 적이 있는 칸은 막을 수 없다.
- **미리 계산**: 행동 하나의 결과(대기·승리·패배)를 현재 상태의 복사본으로 계산한다. 현재 전투는 바뀌지 않는다. 대본의 자유 진행이 패배할 이동을 막는 데 쓴다.

## 검증과 제한

자동 테스트 실행 방법과 전체 통과 수는 [개발 및 사용 가이드](IBIIIS_개발_및_사용_가이드.md)의 자동 테스트 항목에 있다.

- **자동 테스트로 확인한 판정**: 플레이어·적 동시 시작과 서로 다른 완료 시간, 프레임 분할에 무관한 판정, 동시 다중 충돌·엇갈림 비충돌, 2칸 이동의 중간/최종 충돌, 생존 적 경로 피격, 벽 반사, 대시 중간 점유·공유 회피기 제한, 조준이 행동 직전 위치를 쓰는지(인식 칸을 떠나는 행동은 인식, 들어오는 행동은 미인식), 행동 목록(이전 `moveCells` 방식과 동등한 결과, 전진 사이·제자리 회전, 잘못된 칸 수 거부, 빈 목록에만 적용되는 변환), 되돌리기의 전체 상태 복원·진행 중 거부, 범위 계산의 인식 반영·맵 밖 칸 제외, 입력(기본 키 변환·동시 입력 우선순위·반복 방지·재바인딩·누락 액션 시 기본 배치), 배치 Undo·저장/로드·Scene 미리보기·설정 독립성.
- **자동 테스트로 확인한 연출**: 충돌 기록의 칸·단계·참여 적, 충돌 멈춤이 결과를 바꾸지 않음, 연출 중 입력 차단·연출 후 숨김·카메라/외형 복원, 멈춤 동안 다른 적 정지 후 재개, 연출 중 되돌리기 복원, 연출 끔/설정 없음 처리, 플레이어 패배 시 맞힌 적 기록.
- **Play 모드 개발 검증**(입력 주입·코드로 시간 진행): Space 대기와 Backspace 되돌리기의 실제 실행 경로, `ProtoTypeMap`의 승리 경로 11행동(충돌 연출 2회·효과음·승리)과 패배 경로 3행동(카메라 복원·되돌리기 복원), 콘솔 오류 없음. 플레이어 패배 연출은 이후 바뀌어(상황별 플레이어 그림) 이 확인에 포함되지 않는다.
- **사용자 확인 대기**: [플레이 확인 목록](IBIIIS_플레이_확인_목록.md) B-02~B-04·E-07.
- 적 조준 기준을 행동 직전 위치로 바꾸면서(2026-10-06) 이미 만든 맵의 클리어 가능 여부·난이도가 달라질 수 있다. 맵별 확인은 사용자 확인 대기([플레이 확인 목록](IBIIIS_플레이_확인_목록.md) B-11)이며, 맵 에디터의 `검증` 탭으로 다시 분석할 수 있다.
